## 🏢 Контекст и Боли клиента
ООО «Ромашка» — российская компания, работающая в сфере газификации, теплоэнергетики и промышленной безопасности. Помимо основного бизнеса, компания реализует **образовательное предприятие**: разрабатывает обучающие программы, проводит аттестации и выдаёт официальные удостоверения, дипломы и свидетельства.

**Главные боли (до внедрения):**
1. **Ручной учёт обучения.** Курсы, документы и счета велись в разных файлах и отделах. Удостоверения и акты заполнялись в Excel с нуля — ошибка в ячейке ломала отчёты.
2. **Разрозненные системы.** «1С:Бухгалтерия» и «1С:ЗУП» работали с базовой синхронизацией. Обмен с отделом обучения шёл вручную: бухгалтеры выгружали файлы, отправляли по почте и ждали синхронизацию.
3. **Дубли и беспорядок в НСИ.** В базе накопились данные за годы, справочники дублировались, логика процессов отсутствовала.
4. **Отсутствие единой картины.** Не было единой картины по продажам, обучающим программам и расчётам с клиентами.
5. **Требования ФИС ФРДО.** Нужно было реализовать учёт по реестру ФИС ФРДО для выпуска удостоверений и сертификатов.

## 🎯 Архитектурное решение (Что сделали)
Создали единую систему, где обучение, продажи и учёт синхронизированы между собой.

1. **Объединили системы.** Перенесли данные из «1С:Бухгалтерия предприятия» в «1С:УНФ». Настроили прямую синхронизацию между системами через общий сервер с веб-доступом.
2. **Автоматизировали продажи.** В блок продаж (документ «Заказ покупателя») добавили: выбор программы обучения из справочника номенклатуры; формирование реализаций товаров и услуг; автоматическую печать договоров и счетов по собственным шаблонам; передачу данных в бухгалтерию без ручных выгрузок.
3. **Автоматизировали учёт образовательных программ.** Для каждой программы фиксируются: вид удостоверения, код программы, количество учебных часов. На базе заказа покупателя создаётся документ «Оформление удостоверений», где указываются слушатели, серия и номер документа, тип удостоверения. Номера назначаются автоматически.
4. **Доработали под ФИС ФРДО.** Настроили кодировки программ и справочников, сформировали связи с государственным реестром, автоматизировали печать удостоверений, дипломов и сертификатов.
5. **Внедрили закупки и казначейство.** Выстроили полный цикл движения денег: заказ поставщику → заявка на расход → реестр платежей → подпись руководителя → оплата. Настроили контроль кассовых разрывов по дате и доступным средствам.

## 💡 Нестандартные приемы и доработки
*   **Нештатная бесшовная интеграция с 1С:ДО через веб-сервис.** В УНФ отсутствует штатная интеграция с 1С:Документооборот. Специалист сделал нештатную бесшовную интеграцию, связав базы данных через веб-сервис. Для этого была произведена настройка процессов в 1С:ДО и сделаны доработки в УНФ.
*   **Справочник «Программы обучения» с кодировкой.** Разработали с нуля справочник, где каждая программа обучения связана со своим кодом, видом удостоверения и количеством часов. Это позволило автоматически подставлять шаблоны и нумеровать документы.
*   **Автоматическая нумерация удостоверений по регионам.** Серии и номера выдаются по региону, что исключает путаницу и ручные ошибки.
*   **Автоматическая печать договоров и счетов по собственным шаблонам.** В заказе покупателя настроена автоматическая печать договоров и счетов по собственным шаблонам. Это ускоряет оформление и снижает количество ошибок.
*   **Контроль кассовых разрывов.** Настроили проверку заявок по дате и доступным средствам, чтобы исключить перерасход. Казначейство стало управляемым инструментом.

## 🧠 Выводы для внедренца
1.  **Обучение — это отдельный бизнес-процесс, и его нужно автоматизировать.** В УНФ нет готового модуля для образовательных услуг (учёт программ, выдача удостоверений, ФИС ФРДО). Всё это пришлось создавать с нуля (справочники, документы, печатные формы).
2.  **Интеграция с 1С:ДО через веб-сервис — рабочее решение.** Если у клиента есть документооборот, и штатной интеграции нет, можно сделать бесшовную связку через веб-сервис. Это требует доработок с обеих сторон.
3.  **Казначейство в УНФ работает.** Настроили полный цикл: заказ → заявка → реестр → подпись → оплата. Плюс контроль кассовых разрывов. Это даёт управляемость финансами.
4.  **Обучение после каждого блока.** На проекте обучение проводилось после каждого этапа (продажи → ФИС ФРДО → казначейство). Это позволило пользователям постепенно осваивать систему и не перегружаться.
5.  **40+ пользователей — это серьёзная нагрузка.** Для такого количества людей нужна чёткая структура прав доступа и продуманные интерфейсы. Иначе будет хаос.
