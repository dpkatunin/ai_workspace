# _meta/ — метаданные базы знаний

Здесь живут служебные файлы, которые описывают, как устроена база знаний.

## Что здесь лежит

| Файл | Что это | Кто использует |
|---|---|---|
| `taxonomy.yaml` | Таксономия: все допустимые значения полей frontmatter | Пайплайн PDF, агент, скрипты |
| `config_registry.yaml` | Реестр конфигураций 1С: версии, семейства, связи | Агент, скрипты, пайплайн |
| `sources.md` | Журнал: какой PDF → какой MD | Автоматически пайплайном |
| `gaps.md` | Реестр пробелов (чего в базе знаний нет) | Человек + агент |
| `pipeline_log.md` | Журнал прогонов пайплайна PDF | Автоматически |
| `cross-map.md` | Карта кросс-связей между конфигурациями | Человек |

## Как это связано

```

taxonomy.yaml ─────┐
├──→ определяет поля frontmatter в каждом MD-файле
config_registry.yaml ─┘

┌──→ пайплайн PDF генерирует черновики
taxonomy.yaml ─────┤
└──→ агент фильтрует и ищет по правилам

```

## Три оси в taxonomy.yaml

**Аналогия из 1С:** это как измерения регистра накопления. Каждый файл
одновременно имеет три координаты.

| Ось | Значения | Зачем |
|---|---|---|
| `config` | unf, erp, zup, universal, ... | Отделить УНФ от ERP |
| `type` | reference, practical, case, ... | Отделить теорию от практики |
| `level` | kb, project | Отделить общее от клиентского |

## Как добавить новую конфигурацию

1. Добавить `id` в `taxonomy.yaml` → `configs`.
2. Добавить карточку в `config_registry.yaml` → `configs`.
3. Создать структуру `_configs/{id}/` (см. заметки в registry).
4. Обновить `families` и `cross_comparisons`.

## Как добавить новый раздел

1. Добавить запись в `taxonomy.yaml` → `sections`.
2. Указать `applicable_to` — к каким конфигурациям применим.
3. Указать `concepts` — какие concepts покрывает.
4. Добавить `keywords` — для классификатора PDF.

## Глоссарий терминов из taxonomy

**`concept`** — семантический тег «о чём файл», не зависящий от
конфигурации. Файл про склад в УНФ и файл про склад в ERP имеют
одинаковый concept `warehouse`. Это позволяет агенту на запрос
«сравни склад в УНФ и ERP» найти оба файла по одному тегу.

**`applicable_to`** — список конфигураций, к которым применим раздел.
Биллинг есть только в УНФ, налоги — в УНФ, БП и ERP. Без этого поля
агент мог бы галлюцинировать «биллинг в ЗУП».

**`aliases`** — старые имена файлов. Существующие файлы называются
`05_СкладСклад_Объекты.md`, а канонический id — `warehouse`. Aliases
позволяют парсеру сопоставить одно с другим при миграции.

**`routing_rules`** — правила, как агент выбирает, где искать ответ.
Это не код, а декларация, которая идёт в README агента.
