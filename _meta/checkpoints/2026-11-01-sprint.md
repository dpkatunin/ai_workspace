## 4. Что сделать вручную (агенту недоступно)

Удаление файлов и пересборка индексов выполняются в репозитории:

```bat
git rm kb\unf30\pitfalls\pit-marketplejsy.md

git add kb\unf30\pitfalls\pit-integracii-edo.md

```

После пересборки проверить: `search_kb("заказы с маркетплейса не собираются в отгрузку")` должен вернуть **одну** карточку — `unf30-pit-integracii-marketplejsy`.

## 5. Статус карточек — почему оставлен draft

По conventions §3: «`verified` = все содержательные утверждения подтверждены практикой / ИТС / конфигурацией. Структурная чистота ≠ verified».

Что сделано:

- `verify_card_facts` по обоим канонам — **все объекты найдены в конфигурации** (справочник «Номенклатура», `НастройкиПодключенияКОФД` и др.).
- Ссылки живые (после правки playbook).
- В `by-synonym` входы есть, включая перенесённые.

Чего не хватает для `verified`: подтверждения **содержательных** утверждений на практике или по ИТС. Источник канонов — внешние материалы (TopKoder, ИТС 1С, Spark), «на практике внедренца не проверялось».

**Решение за пользователем:** если пункты 1–4 по маркетплейсам и ЭДО соответствуют тому, что видно на базе клиента / в ИТС, — статус меняется на `verified` одной правкой frontmatter и пересборкой индексов.
