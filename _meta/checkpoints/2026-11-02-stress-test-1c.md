## Регистр `ОписаниеНоменклатурыИС` (прогон 5, verified по XML)

**Свойства:** `Nonperiodical`, `WriteMode = Independent` (не подчинён регистратору), `UseStandardCommands = false`.

**Измерения — 1:**
- `Номенклатура` — `DefinedType.ИсточникОписанияНоменклатурыИС`, `Master = true`, `MainFilter = true`, `FillChecking = ShowError`, `Indexing = DontIndex`.

**Ресурсы — 8:**
1. `ЕмкостьПотребительскойУпаковки` — decimal(13,3), ≥0
2. `КоличествоВПотребительскойУпаковке` — decimal(18,8), ≥0
3. `ВариантЧастичногоВыбытия` — EnumRef.ВариантыУчетаЧастичногоВыбытияИС
4. `ВариантИспользованияЕдиницыХранения` — EnumRef.ВариантыИспользованияЕдиницыХраненияИС
5. `ПотребительскаяУпаковка` — DefinedType.Упаковка
6. `УпаковкаЧастичногоВыбытия` — DefinedType.Упаковка
7. `КлючВидовПродукции` — CatalogRef.КлючиВидовПродукцииИС
8. `ИдентификаторыВидовПродукции` — v8:ValueStorage

**Как попадают записи:** в метаданных регистра не описано. `WriteMode = Independent` → записывается программно, не документами. В `_raw/unf30_xml/` кода нет — конкретное место записи не подтверждено.

## Дефекты, найденные за стресс-тест

1. **Память BDS недостаточна** (прогон 1). Без `START-HERE` агент не знает про обязательный `search_config`, отвечает из памяти, воспроизводит старые галлюцинации.
2. **Зацикливание при подмене инструмента** (прогоны 3, 4). Харнесс возвращает веб-поиск вместо MCP; агент повторяет 19 раз вместо двух. Закрыто §12.2 (две попытки → стоп).
3. **`search_kb` без порога покрытия** (прогоны 4, 5). Отдаёт 5 карточек с релевантностью 0.79–0.82 на запрос, где темы нет. Нужен порог «нет покрытия» или явный флаг.
4. **`DefinedTypes` отсутствуют в XML-выгрузке** (прогон 5). Вопрос «какого типа измерение» упирается в скоуп парсера. Кандидат в backlog `config_parser_decision`.
5. **`read_config_file` не отличает** «нет файла» от «нет такого вида метаданных». Нужен список доступных корневых папок выгрузки.

## Принятые решения по контракту

- **§10:** ответ без единого вызова `search_config` в `/1c` недействителен.
- **§12.1:** одна повторная попытка при ошибке MCP → явное сообщение → ответ с пометкой.
- **§12.2:** две неудачные попытки при подмене инструмента → стоп → явное сообщение.
- **Якорный пример расширен:** «Ввод в оборот» — не документ, а Enum `СпособыВводаВОборотСУЗ`. Русская формулировка может совпасть с именем перечисления, а не документа.

## Содержательный вывод по вопросу №6 (GENERAL, не верифицировано)

- ЧЗ оперирует кодами (КМ), а не сериями. Серия — внутренняя аналитика 1С.
- Пересорт между сериями одной номенклатуры для ЧЗ — не событие.
- Недостача → `ВыводИзОборотаИСМП` (подтверждено).
- Излишки — три сценария по статусу кода в ЧЗ:
  1. Код выбыл по вашему документу → `ВозвратВОборотИСМП` с `ВидВозврата`.
  2. Код за другим участником → автоматически «присвоить» нельзя, разбор с поставщиком.
  3. Код не найден → перемаркировка.
- **Карточек KB по маркировке нет.** Ответ только из GENERAL.
