# Стресс-тест режима `/1c`: инвентаризация и маркировка

**Дата:** 2026-11-02
**Статус:** в работе. KB не наполняем, пока тест не закрыт.

## Вопрос стресс-теста

> УНФ 3.0, маркируемая одежда. Инвентаризация выявила недостачу и излишек на одной номенклатуре и характеристике, но разных сериях — пересорт. По недостаче — вывод из оборота ИСМП. Что делать с излишками? Как сказать «Честному знаку», что марки числятся за мной? По данным ЧЗ они не на мне.

## Что тестируем

Режим `/1c` по контракту: обязательный `search_config` до ответа, затем GENERAL (логика) + CONFIG (имена) + KB (поведение). Отказ запрещён.

## Прогоны

| № | Условия | MCP-вызовы | Результат |
|---|---|---|---|
| 1 | Без START-HERE, только память BDS | 0 | Полный ответ, но «причина возврата» вместо `ВидВозврата`. Память недостаточна. |
| 2 | Со START-HERE, контракт без обязательного search_config | 0 | Ответ полный, но «Ввод в оборот» (не существует) и «Списание КМ» (правильно `СписаниеКодовМаркировкиИСМП`). |
| 3 | Со START-HERE, контракт с обязательным search_config | 19 попыток, 0 успешных | Агент зациклился: харнесс возвращал веб-поиск вместо MCP. В конце — «MCP-проверка не выполнена (лимит шагов)». |

## Найденные дефекты

1. **Память BDS недостаточна.** Без START-HERE агент не знает про обязательный `search_config` и формулу GENERAL+CONFIG+KB. Отвечает из памяти, воспроизводит старые галлюцинации.
2. **Зацикливание при подмене инструмента.** Когда харнесс возвращает веб-поиск вместо MCP, агент повторяет попытку 19 раз вместо двух.

## Принятые решения

- §10: ответ без `search_config` в `/1c` недействителен.
- §12.1: одна повторная попытка при ошибке MCP.
- §12.2: две неудачные попытки при подмене инструмента → стоп, явное сообщение, ответ с пометкой.

## Содержательный вывод по вопросу (GENERAL, не верифицировано)

Вопрос про пересорт маркированной одежды. Логика (GENERAL):
- ЧЗ оперирует кодами, а не сериями. Серия — внутренняя аналитика 1С.
- Для ЧЗ пересорт между сериями одной номенклатуры — не пересорт. Важен статус каждого кода.
- Недостача закрыта `ВыводИзОборотаИСМП` — корректно (CONFIG подтверждён).
- Излишки: три сценария по статусу кода в ЧЗ (выбыл/чужой/не найден). Точная процедура — по факту статуса.

**Ни одна карточка KB тему маркировки не покрывает.** Содержательный ответ возможен только из GENERAL с пометкой.
