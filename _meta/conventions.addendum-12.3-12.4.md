## Дополнение к §10.1 — блок «Вызовы в этом прогоне»

### Обязательный элемент ответа `/1c`

В начале ответа, **до** «Короткого ответа», — таблица фактических вызовов инструментов в этом прогоне:

```

## Вызовы в этом прогоне

| Инструмент ↕▾ | Запрос / аргумент ↕▾ | Результат ↕▾ |
|---|---|---|
| −search_config | ПересортицаЗапасов | ✅ Document.ПересортицаЗапасов |
| search_kb | пересортица маркировка ЧЗ | ✅ top-1 = 0.842 (unf30-pit-sklad) |
| WEB (AUTO:SEARCH) | пересортица ЧЗ урегулирование | ⚠️ 1-я попытка: вендор-блоги; 2-я: пусто |
| read_config_file | Enums/ВидыОперацийИСМП.xml | ✅ |
⚙

```

**Правила заполнения.**

1. Строка таблицы = фактический вызов инструмента. Нет вызова — нет строки.
2. «Результат»: ✅ (получено нужное), ⚠️ (получено неудовлетворительное), ❌ (ошибка / пусто).
3. Таблица заполняется **по транскрипту**, а не по памяти о предыдущих прогонах.
4. Если инструмент не вызывался — явно пишется в оговорках: «`search_kb` не вызывался», а не «не дал результатов».

### Маркеры источника — три уровня

| Маркер | Значение | Когда ставить |
|---|---|---|
| ⚙️ CONFIG / 🌐 WEB / 📗 KB | Подтверждено выводом инструмента **в этом прогоне** | Есть соответствующая строка в «Вызовы в этом прогоне» |
| 📝 ПАМЯТЬ | Взято из чекпоинта или предыдущего прогона | Формат: `📝 прогон N` или `📝 чекпоинт YYYY-MM-DD` |
| ⚠️ не верифицировано | Память модели без опоры на KB/CONFIG/WEB | В блоке «Оговорки» обязательно — где проверять |

**Правило «нет вывода — нет маркера».** Маркер `🌐`, `⚙️`, `📗` без вывода инструмента в этом прогоне — дефект Д17, ответ недействителен.

### Пример — плохо / хорошо

**Плохо (инцидент 2026-11-03):**
> ⚙️ **CONFIG**: `search_config("ПересортицаЗапасов")` → `Document.ПересортицаЗапасов` ✅.
> 🌐 **WEB** ([support.kontur.ru](https://support.kontur.ru)): «Участник оборота обязан…»

Факт: `search_config` вызван один раз, WEB — **ноль** раз. Цитата сконструирована.

**Хорошо:**
> ⚙️ **CONFIG**: `search_config("ПересортицаЗапасов")` → `Document.ПересортицаЗапасов` ✅ (см. «Вызовы в этом прогоне», строка 1).
> 📝 **ПАМЯТЬ** (прогон 7): `ВыводИзОборотаИСМП` — подтверждён ранее, в этом прогоне не проверялся.
> ⚠️ **не верифицировано**: причина вывода «Пересортица по кодам» — по обучающим данным, в WEB/CONFIG не подтверждена. Где проверять: `ВыводИзОборотаИСМП → ПричинаВывода` (XML) или docs.crpt.ru.

## §12.3. Неудовлетворительный WEB — обязательный повтор

### Определение

WEB-поиск вернул непустой результат, но результат **не пригоден** для подтверждения ключевого звена ответа. Триггер — любой из трёх признаков:

- **(а)** в выдаче нет ни одного источника класса `[ИТС]` / `docs.crpt.ru` / официальной документации 1С;
- **(б)** ключевое звено (имя документа, вид операции, порядок шагов, имя реквизита) держится **только** на `[ВЕНДОР-БЛОГ]` / `[ФОРУМ]`;
- **(в)** целевая страница загрузилась пустой / только оглавлением / HTTP 429.

### Обязательный повтор

Одна повторная попытка с **изменённым параметром**:

| Что менять | Пример |
|---|---|
| `sourceType` | `general` → `docs`; `docs` → `general` |
| `deepFetch` | `0` → `2`; `2` → `3` |
| Формулировка | добавить «официальная инструкция», «ИТС», «docs.crpt.ru»; убрать лишние слова |

Повтор с **тем же** запросом и **тем же** параметром — не считается повтором.

### Исход повтора

- **Удовлетворительно** — ключевое звено подтверждено источником класса не ниже ИТС → использовать.
- **Неудовлетворительно** — в ответе явно: «первоисточник не получен: <что искали>». Цитату из памяти **не подставлять**. Факт — `⚠️ не верифицировано`.
- **Техническая ошибка** — см. §12.1 / §12.2.

### Что НЕ является поводом для повтора

- Другой вопрос / другое имя объекта — это **новый** вызов, а не повтор. «Две попытки» = две попытки получить **тот же** результат.
- Проверка пяти имён в CONFIG — пять разных запросов, не пять попыток. Число вызовов CONFIG фиксируется в блоке «Вызовы в этом прогоне», но лимит §12.3 на них не распространяется.

### Связь с §10.1

Если §12.3 применим (ключевое звено на вендор-блоге) — это **стоп-сигнал**. Ответ не собирается, пока не потрачена вторая попытка WEB. Это правило уже действовало в прогоне 6 (checkpoint 2026-11-02); §12.3 закрепляет его как норму, а не как разовое решение.

## §12.4. Арифметический тест маркеров источника

### Правило

**Число маркеров источника в ответе ≤ число фактических выводов инструментов в этом прогоне.**

Считаются: `🌐`, `⚙️`, `📗`. Не считаются: `📝 ПАМЯТЬ`, `⚠️ не верифицировано`.

### Как применять

Перед отправкой:
1. Посчитать выводы в блоке «Вызовы в этом прогоне».
2. Посчитать маркеры `🌐`/`⚙️`/`📗` в тексте ответа.
3. Если маркеров больше — **сокращать**, а не досочинять.

Пример: 1 `search_config` + 0 `search_kb` + 0 WEB = 1 вывод. 10 маркеров в тексте = 9 лишних. Допустимо: 1 ⚙️, остальные — `📝` или `⚠️`.

### Смысл

Дефект Д17 (подмена памяти выводом) проявляется именно как **разрыв** между числом маркеров и числом вызовов. Арифметический тест ловит разрыв до отправки, не требуя разбирать каждую цитату.

## Чек-лист `/1c` перед отправкой (обновлённый)

1. `search_config` — минимум один вызов, вывод в «Вызовы в этом прогоне».
2. `search_kb` — вызов есть; если top-1 < 0.85 или тема мимо — «нет в KB».
3. WEB (если KB пуста) — вызов есть; при неудовлетворительном результате — вторая попытка с изменённым параметром (§12.3).
4. `read_config_file` — если вопрос про внутреннее устройство объекта; путь плоский (`Documents/<Имя>.xml`, `Enums/<Имя>.xml`).
5. Блок «Вызовы в этом прогоне» заполнен по транскрипту.
6. Маркеры: `🌐`/`⚙️`/`📗` только на свежие выводы; `📝 прогон N` для старых; `⚠️` для неверифицированных.
7. Арифметический тест (§12.4): маркеров ≤ выводов.
8. Блок «Что не подтверждено и где проверять» — обязателен, если есть хотя бы один `⚠️`.
