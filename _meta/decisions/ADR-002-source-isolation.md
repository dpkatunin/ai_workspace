# ADR-002: Изоляция исходных материалов

## Контекст

В корне репозитория лежал каталог `00_knowledge_base/` — исходные материалы (≈60 файлов: функциональные разделы УНФ 3.0 и 15 кейсов внедрений), из которых перерабатываются карточки `kb/`. Каталог не имеет фронтматтера, статусов достоверности и ID. Он остаётся нужным как исторический источник и материал для Фазы 2, но не должен участвовать в RAG.

**Риск:** агент, выполнив поиск по репозиторию (fetch, поиск по файлам, GitHub search), находит старые файлы и отвечает по ним — без цитаты, без статуса, без ID. Это подрывает принцип 4 из ADR-001 (обязательный статус достоверности) и обесценивает структуру `kb/`.

Аналогия из 1С: исходники — это выгрузка конфигурации в XML. Она нужна для генерации, но не является рабочим справочником. Никто не даёт пользователю искать по выгрузке напрямую — он ищет по справочникам в рабочей базе.

## Решение

1. Каталог `00_knowledge_base/` переименован в `_source/`. Он остаётся в репозитории как исторический источник.
2. В `_meta/navigator-prompt.md` прописан явный запрет: не читать `_source/` при ответе на вопросы.
3. В `_meta/index.md` каталог `_source/` указан как архив, не как источник знаний.
4. Каталоги с ведущим `_` (`_meta/`, `_source/`) — служебные. `kb/` и `projects/` — рабочие. Правило зафиксировано в `_meta/conventions.md`.
5. В `README.md` явно описано назначение `_source/`.

## Альтернативы

- **Удалить `00_knowledge_base/`** — отвергнуто: исторический источник и материал для Фазы 2, понадобится при переработке.
- **Оставить без переименования, полагаться только на правило в навигаторе** — отвергнуто: правило легко нарушить, а префикс `_` даёт явный сигнал и человеку, и агенту.
- **Перенести в отдельный репозиторий** — отвергнуто на текущем масштабе: усложняет работу без выгоды.

## Последствия

- Агент видит `_source/` как служебный каталог и не цитирует его.
- Человек при просмотре репозитория видит разделение: `_meta/` — правила, `_source/` — архив, `kb/` + `projects/` — рабочие знания.
- Ссылки на старые файлы из карточек `kb/` не делаются. Если нужна ссылка на источник — используется поле `source` во фронтматтере.
- Переименование — одна операция в Git (`git mv 00_knowledge_base _source`), история файлов сохраняется.

## Условия пересмотра

- **Полная переработка `_source/` в `kb/`** — после этого `_source/` можно удалить и пересмотреть этот ADR.
- **Появление второй конфигурации** — структура `_source/` может потребовать подкаталогов по конфигурациям (`_source/unf30/`, `_source/erp/`).
