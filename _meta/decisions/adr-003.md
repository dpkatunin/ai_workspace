# ADR-003. Автоматизация индексов `by-synonym` и `by-movement`

## Контекст

Два инцидента подряд с одной причиной:

1. **Q14 baseline/retest.** `_index.md` описывал `doc-sdelnyy-naryad` как «фиксация выработки». Карточка покрывает ещё и начисление зарплаты с проводкой Дт 20.40 Кт 70. Агент на baseline сделал вывод «процедуры начисления в базе нет» — ложный отказ из-за одной строки в ручном индексе.
2. **Q15 retest.** `by-movement.md` отработал идеально — за один запрос, дешевле всех остальных маршрутов. Но он ручной: при следующем изменении карточек разъедется так же, как `_index.md`.

Вывод: ручной индекс — это **вторая копия знания**. Любая вторая копия расходится с первой. Это не вопрос дисциплины, это структурный дефект.

## Решение

Индексы `_meta/by-synonym.md` и `_meta/by-movement.md` **генерируются скриптом** из карточек. Ручное редактирование запрещено.

### Контракт парсера

**1. Фронтматтер карточки** — источник для `by-synonym.md`:

id: unf30-cat-kontragent        # обязателен, уникален
type: object                    # object | mechanism | playbook | pitfall | case
status: draft                   # verified | draft | outdated
synonyms: [контрагент, юрлицо]  # опционально, список строк
