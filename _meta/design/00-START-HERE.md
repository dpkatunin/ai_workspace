# 00-START-HERE.md

**Прочитай это первым, если ты агент в новом чате.** Этот файл — сжатый дайджест всего проекта, чтобы ты вник в контекст за 2 минуты.

## Режимы работы

| Команда | Что делает |
|---|---|
| `/1c` | Включить режим 1С: поиск по KB + CONFIG, маркировка источников |
| `/1c off` | Выключить режим 1С (обычный чат) |
| `/tags` | Показать справку |

**По умолчанию чат — обычный.** Агент не трогает KB и CONFIG, пока не включён `/1c`.
**Отказ запрещён.** Если в KB нет ответа — дать общий ответ с маркировкой «не верифицировано».

Если в обычном чате задан вопрос по 1С — один раз за сессию напомни про `/1c`.

## Что это за проект

База знаний 1С (RAG) для быстрого входа в незнакомые конфигурации. УНФ 3.0 — полигон. Завтра будут ERP, КА и др.
Пользователь — внедренец 1С с 25-летним опытом. Работает в том числе на субподряде. Цель — чтобы агент помогал в реальной работе с клиентом (давал проверяемые ответы со ссылками), а не просто «красиво отвечал» или отказывался.

## Как со мной работать (правила)

1. **Сначала поиск (в режиме `/1c`):** перед ответом на вопрос по 1С вызывай `search_kb` и `search_config`.
2. **Отказ запрещён:** если в KB нет — дай ответ с маркировкой «не верифицировано», перечисли что искал. Не молчи.
3. **Статусы:** сейчас все карточки `verified`. Если появится `draft` — предупреди.
4. **Ссылки:** отвечай с указанием `id` карточки.
5. **Проверка фактов:** для точных имён объектов и реквизитов — `search_config` и `read_config_file`.
6. **Сверка карточек:** перед выдачей готовой карточки прогони через `verify_card_facts`.
7. **Запреты:** `_source/` агентом не читается (ADR-002).
8. **Индексы руками не править:** генерируются `tools/build_indexes.py` (ADR-003).

## Контракт агента в режиме `/1c`

1. Два поиска: `search_kb` (поведение) + `search_config` (имена).
2. Один ответ с блоками: **Поведение (KB)**, **Объекты (CONFIG)**, **Общий порядок (не верифицировано)**.
3. Если в KB нет — сказать прямо, но дать общий ответ с пометкой.
4. Любое имя объекта/реквизита — только из CONFIG. Если не подтверждено — «требует проверки».
5. «Не найдено запросом X» ≠ «объекта нет». Формулируй «не подтверждено».

## Если в KB нет ответа (playbook)

1. Напиши: «В KB нет карточек по теме <тема>» — это факт, не отказ.
2. Перечисли, что искал: запросы `search_kb`, топ-3 с `id`.
3. Дай общий ответ по теме с пометкой «не верифицировано».
4. Для имён объектов укажи подтверждённые из CONFIG или «требует проверки».
5. Предложи завести карточку в KB.
