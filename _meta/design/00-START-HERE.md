# 00-START-HERE.md

**Прочитай это первым, если ты агент в новом чате.** Этот файл — сжатый дайджест всего проекта, чтобы ты вник в контекст за 2 минуты.

## Режимы работы (теги)

| Тег | Что делает |
|---|---|
| `/kb` (по умолчанию) | Только KB, стоп если пусто |
| `/kb+` | KB → CONFIG → GENERAL, GENERAL помечен «не верифицировано» |
| `/cfg` | Только CONFIG (метаданные) |
| `/free` | Черновик, GENERAL разрешён |
| `/tags` | Показать эту таблицу |

Нет тега = `/kb`. Забыл теги — напиши `/tags` или открой `design/10-cheatsheet.md`. Подробно — `conventions.md` §10.

## Что это за проект

База знаний 1С (RAG) для быстрого входа в незнакомые конфигурации. УНФ 3.0 — полигон. Завтра будут ERP, КА и др.
Пользователь — внедренец 1С с 25-летним опытом. Работает в том числе на субподряде. Цель — чтобы агент помогал в реальной работе с клиентом (давал проверяемые ответы со ссылками), а не просто «красиво отвечал».

## Как со мной работать (правила)

1. **Сначала поиск:** перед ответом на любой вопрос по 1С вызывай `search_kb`.
2. **Только по карточкам:** если в базе нет ответа — скажи «нет в KB», перечисли что искал и остановись (playbook ниже). Не достраивай по общим знаниям.
3. **Статусы:** сейчас все карточки `verified`. Если появится `draft` — предупреди, выдавать за факт запрещено.
4. **Ссылки:** отвечай с указанием `id` карточки.
5. **Проверка фактов:** для точных имён объектов и реквизитов — `search_config` и `read_config_file`.
6. **Сверка карточек (ЖЕЛЕЗНОЕ ПРАВИЛО):** перед выдачей готовой карточки прогони текст через `verify_card_facts`. Если `❌` — найди правильные имена через `search_config` и исправь.
7. **Запреты:** `_source/` агентом не читается (ADR-002). Ссылки на `_source/` в карточках запрещены (conventions §9).
8. **Индексы руками не править:** `by-synonym.md` и `by-movement.md` генерируются `tools/build_indexes.py` (ADR-003).
9. **Первый ответ в новом чате** начинай строкой: «Режимы: /kb /kb+ /cfg /free /tags. По умолчанию /kb.»

## Контракт агента (обязателен в любом режиме)

1. Отвечай по карточкам KB с указанием `id`.
2. Если в KB нет — «нет в KB», перечисли что искал, не достраивай.
3. Любое имя объекта/реквизита — только из CONFIG (`search_config` / `read_config_file`).
4. «Не найдено запросом X» ≠ «объекта нет». Формулируй «не подтверждено».
5. Каждый факт маркируй: `KB (id)` / `CONFIG (файл)` / `не подтверждено` / `не верифицировано`.
6. GENERAL — только для формулировки поискового запроса, не для ответа.

## Если в KB нет ответа (playbook)

1. Напиши: «В KB нет карточек по теме <тема>».
2. Перечисли, что искал: запросы `search_kb`, топ-3 с `id` и релевантностью.
3. Если тема мимо — скажи «топ нерелевантен», не выдавай его за ответ.
4. Предложи: (а) `/kb+` — ответ с маркировкой «не верифицировано»; (б) `/cfg` — проверка имён; (в) завести карточку в KB.
5. Не выдавай имена объектов из GENERAL.
