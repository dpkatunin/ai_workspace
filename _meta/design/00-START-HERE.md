## Как со мной работать (правила)

1. **Сначала поиск (в режиме `/1c`):** перед ответом вызывай `search_config` (обязательно), затем `search_kb`, при пустой KB — WEB.
2. **Отказ запрещён:** если в KB нет — дай ответ из GENERAL или WEB, проверь имена в CONFIG, пометь «не верифицировано».
3. **Статусы:** все карточки `verified`. Если появится `draft` — предупреди.
4. **Ссылки:** указывай `id` карточки из KB.
5. **Проверка имён:** для объектов и реквизитов — `search_config` и `read_config_file`.
6. **Сверка карточек:** перед выдачей готовой карточки прогони через `verify_card_facts`.
7. **Запреты:** `_source/` не читается (ADR-002).
8. **Индексы руками не править** (ADR-003).

## Контракт агента в режиме `/1c`

**Обязательный порядок:**

0. **`search_config` — до ответа.** Выбери из вопроса минимум одно имя объекта и вызови `search_config`. Пока вызова не было — ответ не начинай. **Ответ без единого вызова `search_config` недействителен.**
1. **`search_kb`** — проверка базы. Если top-1 ниже 0.85 или тема мимо — «нет в KB», переходи дальше.
2. **WEB** — внешний поиск, если KB пуста. Для каждого факта — источник.
3. **CONFIG** — проверка КАЖДОГО имени из WEB. Для каждого — вывод инструмента. Имя без вывода = «не подтверждено».
4. **Сборка ответа** по формату §10.1 (см. ниже).
5. **Никаких отказов.** «В KB нет» — это факт, а не причина молчать.

**Якорные примеры:**
- «Ввод в оборот» — не документ. Есть `ВозвратВОборотИСМП` и `СписаниеКодовМаркировкиИСМП`.
- «Маркировка остатков» — не документ и не табличная часть, а значение перечисления `ВидыОперацийИСМП.ВводВОборотМаркировкаОстатков`.

## Формат ответа в `/1c` (кратко)

Полная версия — `conventions.md` §10.1. Порядок блоков:

1. **Короткий ответ** — 2–3 строки, жирным.
2. **Схема (Mermaid) или таблица шагов** — что не дублировать.
3. **Детали по шагам** с маркерами: 📗 `KB` / 🌐 `WEB` / ⚙️ `CONFIG` / ⚠️ «не верифицировано».
4. **Выноска «не путать»** — если рядом есть похожие по имени объекты.
5. **Чек-лист «проверить перед стартом»** — 3–5 пунктов.
6. **Оговорки и пробелы** — в конце.

Красота = сжатие до структуры, не до слов. Воды, общих рассуждений, дублирования — нет.

## Если MCP недоступен или подменён

1. **Одна повторная попытка** при ошибке связи (§12.1).
2. **Две попытки — предел** при подмене инструмента харнессом (§12.2).
3. Явно напиши: «MCP недоступен, проверка не выполнена: <инструмент>» или «MCP-инструмент подменяется харнессом».
4. Дай ответ из GENERAL или WEB с пометкой «не верифицировано».
5. Предложи проверить сервер: запущен ли `mcp_server.py`, вызов `kb_stats`.
6. Не пиши «не проверял» — пиши «MCP не отвечал».
