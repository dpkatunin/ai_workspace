# 00-START-HERE.md

**Прочитай это первым, если ты агент в новом чате.** Этот файл — сжатый дайджест всего проекта, чтобы ты вник в контекст за 2 минуты.

## Режимы работы

| Команда | Что делает |
|---|---|
| `/1c` | Режим 1С: обязательный `search_config` → GENERAL + CONFIG + KB |
| `/1c off` | Обычный чат |
| `/tags` | Справка |

**По умолчанию — обычный чат.**
**Первый ответ в новом чате** начинается строкой: «Режимы: /1c (по умолчанию — обычный чат). /tags — справка.»

## Что это за проект

База знаний 1С (RAG) для быстрого входа в незнакомые конфигурации. УНФ 3.0 — полигон. Пользователь — внедренец 1С с 25-летним опытом. Цель — проверяемые ответы со ссылками в реальной работе.

## Как со мной работать (правила)

1. **Сначала поиск (в режиме `/1c`):** перед ответом вызывай `search_config` (обязательно) и `search_kb`.
2. **Отказ запрещён:** если в KB нет — дай ответ из GENERAL, проверь имена в CONFIG, пометь «не верифицировано».
3. **Статусы:** все карточки `verified`. Если появится `draft` — предупреди.
4. **Ссылки:** указывай `id` карточки из KB.
5. **Проверка имён:** для объектов и реквизитов — `search_config` и `read_config_file`.
6. **Сверка карточек:** перед выдачей готовой карточки прогони через `verify_card_facts`.
7. **Запреты:** `_source/` не читается (ADR-002).
8. **Индексы руками не править** (ADR-003).

## Контракт агента в режиме `/1c`

**Обязательный порядок:**

0. **`search_config` — до ответа.** Выбери из вопроса минимум одно имя объекта и вызови `search_config`. Пока вызова не было — ответ не начинай. **Ответ без единого вызова `search_config` недействителен.**
1. **GENERAL:** дай полный ответ по логике работы (алгоритм, шаги, бизнес-смысл).
2. **CONFIG:** каждое имя объекта сверь с выдачей. Если не подтверждено — «требует проверки».
3. **KB:** если есть карточка с поведением — используй её и ссылайся на `id`. Если нет — «не верифицировано».
4. **Никаких отказов.** «В KB нет» — это факт, а не причина молчать.

**Якорный пример:** «Ввод в оборот» — такого документа нет (`search_config` не находит). Есть `ВозвратВОборотИСМП` и `СписаниеКодовМаркировкиИСМП`. Русская формулировка ≠ имя объекта.

## Если MCP недоступен или подменён

1. **Одна повторная попытка** при ошибке связи (§12.1).
2. **Две попытки — предел** при подмене инструмента харнессом (§12.2).
3. Явно напиши: «MCP недоступен, проверка не выполнена: <инструмент>» или «MCP-инструмент подменяется харнессом».
4. Дай ответ из GENERAL с пометкой «не верифицировано».
5. Предложи проверить сервер: запущен ли `mcp_server.py`, вызов `kb_stats`.
6. Не пиши «не проверял» — пиши «MCP не отвечал».
