# Техническая схема

## Уровни знаний

```

kb/                — общее знание по конфигурациям (публично)
_shared/         — общее для всех конфигураций
unf30/           — УНФ 3.0
erp/             — 1С:ERP (план)
projects/          — данные клиентов (приватно)
_meta/             — правила, карта, индексы, ADR, design
_source/           — архив исходников (агент не читает)
_raw/              — XML-выгрузки (локально, в Git не идёт)

```

Мультиконфигурация заложена: `kb/<config>/`, а не `kb/unf30/` жёстко.

## Три уровня инфраструктуры

| Уровень | Роль | Что хранит |
|---|---|---|
| **GitHub** | Источник истины | Вся история, коммиты, откат |
| **VPS** | Витрина с MCP | Рабочая копия + сервер поиска |
| **Ноутбук** | Редактор + бэкап | Рабочая копия + локальный `rsync` |

Правило: **правим на ноутбуке → пушим в GitHub → VPS подтягивает (`git pull`)**. Сервер не редактируем, иначе история разъедется.

## Два репозитория

- **`ai_workspace`** — публичный: `kb/`, `_meta/`, `tools/`. Методичка, не жалко.
- **`ai_workspace_projects`** — приватный: `projects/`. Клиентские данные, NDA.

Причина: публичный репо читается с телефона при выключенном ноуте (raw-ссылки). Приватный — только через MCP с токеном. Разделение снимает риск утечки.

## MCP-сервер

Сейчас: локально на ноутбуке, `127.0.0.1:8000`, читает `kb/unf30/`, поиск векторный (fastembed).

Перспектива: переезд на VPS. Тогда доступен с телефона и при выключенном ноуте. Требования: HTTPS (Caddy), Bearer-токен, файрвол (22/80/443).

Инструменты: `search_kb`, `get_card`, `kb_stats` — только чтение. Запись — отдельная разработка (`create_note` через GitHub API), не сейчас.

## Масштабирование

| Карточек | Что нужно |
|---|---|
| до 100 | Текущая схема |
| 100–500 | `search-index.json` (превью вместо чтения `_index.md` целиком), чанкинг карточек, гибридный поиск (вектор + BM25) |
| 500–2000 | Мультиконфиг-поиск (`config` как параметр), дедупликация |
| 2000+ | Векторная БД (pgvector), реранкер |

Порог боли — ~150–200 карточек. Проектировать надо сейчас, переделывать потом больно.

## Пайплайн сырья

```

_source/ (PDF, статьи, курсы)
→ pdf_extract.py (извлечение, отсев шума)
→ chunker.py (смысловые чанки)
→ фильтр на входе: (1) функциональность или маркетинг? (2) дубль? (3) проверяемо?
→ агент: черновик карточки (draft)
→ verify_content.py: L2-сверка с XML-конфигурацией
→ человек: закрыть ⚠️ (L3)
→ build_indexes.py --apply
→ коммит

```

Узкое место — шаг «человек: закрыть ⚠️». Цель — свести его к 5–10 минутам на карточку.

## Что отложено

- **XML-парсер `RegisterRecords`** — сейчас `Registers with writers: 0`. Не влияет на валидацию имён, но без него не работает автопроверка «кто в кого пишет». Чинить — когда дойдёт до массовой верификации.
- **Запись через MCP** — заметки с телефона сейчас через копирование в чат.
- **Проектные карточки в поиске MCP** — после настройки чтения `projects/`.
