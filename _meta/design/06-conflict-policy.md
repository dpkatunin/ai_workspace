# Политика разрешения конфликтов

Что делать, когда новый источник противоречит существующей карточке.

## 1. Конфликт — это не одна ситуация, а пять

Смешивать их нельзя, правила разные.

| Тип | Что происходит | Пример |
|---|---|---|
| **Версионный** | Старый источник описывает старую версию | Статья 2020: «поле X». В 3.0.12 переименовали в Y |
| **Фактический** | Два источника противоречат по факту | Один: «есть поле». Другой: «нет поля» |
| **Контекстный** | Оба правы, но в разных условиях | «В рознице так, в опте иначе» |
| **Уровневый** | Маркетинг vs техника | «Можно всё» vs «только при условии X» |
| **Ошибочный** | Источник врёт | Галлюцинация автора, устаревшая статья |

## 2. Главное правило: статус определяет автоматику

| Статус карточки | Конфликт с новым источником → что делать |
|---|---|
| `verified` | **Никогда не менять молча.** Только карантин → человек |
| `draft` | Можно обновить автоматически — там нечего терять |
| `outdated` | Заменить новым, если он свежее |

`verified` — неприкосновенен. Автоматика может создавать и обновлять только `draft`.

## 3. Карантин вместо «заменить / дубль / спросить»

Трилемма «заменить / создать вторую / спросить» — ложная.
- Заменить — затрём проверенное.
- Создать вторую — дубли.
- Спросить по каждому чанку — паралич.

**Решение: карантин.** Конфликтное утверждение не идёт ни в карточку, ни в мусор. Оно попадает в отдельную очередь, где человек разбирает. Аналогия: новая редакция договора и подписанная старая — их несёт юристу, а не рвёт старую.

## 4. Как обнаружить конфликт (фильтр)

```

Новый чанк
→ vector search по существующим карточкам (top-5)
→ если top-1 релевантность < 0.6 → новое знание, создаём карточку
→ если > 0.6 → сравнение смысла (LLM-судья: «одно? противоречит? дополняет?»)
→ совпадает → пропустить (дубль)
→ дополняет → добавить (если draft) или в карантин (если verified)
→ противоречит → карантин
→ неясно → карантин

```

Из 400 файлов конфликтов с `verified` будут единицы. Основной поток идёт автоматически, карантин — редкая боковая ветка.

## 5. Формат карантина (`_meta/conflicts/`)

```markdown
---
detected: YYYY-MM-DD
source: _source/.../файл.md, стр. N
existing_card: unf30-...
type: version | factual | contextual | unclear
severity: high | medium | low
---

# Новый источник утверждает
> цитата

# Карточка утверждает
> цитата

# Возможные объяснения
- версия (источник за 2020, карточка >=3.0.12)
- сценарий (розница vs опт)
- ошибка источника

# Решение (заполняет человек)
[ ] обновить карточку
[ ] отклонить источник
[ ] создать вторую карточку (контекстный случай)
[ ] уточнить у ИТС / клиента
```

Ничего не теряется: источник сохранён, решение задокументировано.

## 6. Если конфликт не разрешается

Два `verified`-источника (ИТС vs ИТС) говорят разное, оба правы для своих условий:

- В карточку добавить `## Расхождения в источниках` с обеими версиями.
- Статус **понизить** до `draft` — карточка больше не «эталон».
- Агент при ответе **обязан** предупредить: «в источниках расхождение».
