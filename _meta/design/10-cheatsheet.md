# Шпаргалка: режимы работы агента

## Теги

| Тег | Что делает | Когда использовать |
|---|---|---|
| `/kb` (по умолчанию) | Только KB, стоп если пусто | Клиентский вопрос, нужен проверяемый ответ |
| `/kb+` | KB → CONFIG → GENERAL, GENERAL помечен | Разведка: в KB может не быть, но нужно понять тему |
| `/cfg` | Только CONFIG (метаданные) | «Где хранится», «как называется реквизит» |
| `/free` | Черновик, GENERAL разрешён | Исследование, не для клиента |
| `/tags` | Показать эту таблицу | Забыл теги |

**Нет тега = `/kb`.**

## Примеры

**Клиентский вопрос:**
> УНФ 3.0: маркировка одежды и розничная реализация. Как настроить?

Агент: `search_kb` → если нет релевантного → «нет в KB» и стоп.

**Разведка:**
> `/kb+` маркировка одежды в УНФ 3.0

Агент: KB → CONFIG → GENERAL, каждый факт помечен.

**Метаданные:**
> `/cfg` вид продукции для номенклатуры: где хранится

Агент: только `search_config` / `read_config_file`, «не подтверждено» если не найдено.

## Если забыл

1. Напиши `/tags`.
2. Открой `_meta/design/10-cheatsheet.md`.
3. В новом чате агент сам пишет строку режимов (правило 9 в `00-START-HERE.md`).
4. Теги записаны в память BDS (`kb_mode_tags`, importance=always) — приходят в каждом новом чате.

## Что важно

- `/free` — не для клиента.
- Имена объектов — только `/cfg` или CONFIG. GENERAL как источник имён запрещён.
- «Не найдено» ≠ «нет». Формулировка — «не подтверждено».
- Подробно — `conventions.md` §10–13.
