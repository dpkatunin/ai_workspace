# Проектные документы

Здесь — **знание о самой системе**, а не о 1С. Отвечает на вопросы: зачем она, как устроена, почему так, что не решено.

## Что здесь есть

| Файл | О чём |
|---|---|
| `01-vision.md` | Зачем система, кто пользователь, главный сценарий, критерий успеха |
| `02-principles.md` | Принципы устройства: карточка, статусы, источники, верификация |
| `03-architecture.md` | Техническая схема: Git, MCP, VPS, структура папок, масштабирование |
| `04-history.md` | Три попытки построить систему и чему каждая научила |
| `05-open-questions.md` | Нерешённые развилки — что обсуждаем, но ещё не решили |

## Чем это отличается от соседних папок

- **`kb/`** — карточки знаний по конфигурациям (УНФ 3.0 и будущие).
- **`projects/`** — данные клиентов (приватно).
- **`_meta/decisions/`** — принятые ADR (фиксированные решения).
- **`_meta/design/`** — **живое проектирование**. Здесь можно сомневаться, менять, спорить. ADR рождается здесь, а потом «замораживается» в `decisions/`.

## Правило

Если правило здесь противоречит `conventions.md` — прав файл, документ чиним. `conventions.md` — правила ведения базы, `design/` — почему эти правила такие.

## Читать первым

Агенту в новом чате: **сначала `01-vision.md`, потом `03-architecture.md`**. Это даст контекст за две минуты.
