# Паспорт проекта: База знаний 1С для RAG-агента

Этот файл — точка входа для нового чата или нового участника.

## 1. Что мы строим

База знаний по 1С:УНФ 3.0 для RAG-агента (внедренца-аналитика). Репозиторий: `github.com/dpkatunin/ai_workspace`.

Главная цель: агент отвечает на вопросы по внедрению, опираясь на проверенные карточки, с обязательной цитатой (`id`) и статусом (`verified` / `draft`).

## 2. Архитектура

- **Двухуровневый RAG:** `kb/` + `projects/`.
- **Изоляция источника:** `_source/` не читается агентом (только для ручного извлечения знаний) — ADR-002.
- **Типы карточек:** `object`, `mechanism`, `playbook`, `pitfall`, `case`.
- **Навигация:** `_meta/index.md` → `kb/unf30/_index.md` → 1–3 карточки.
- **Промпт агента:** `_meta/navigator-prompt.md` — открывать карточки, не использовать общие знания, статус из фронтматтера, при вопросах о регистрах — сразу в `by-movement.md`.
- **Индексы:** `by-synonym.md`, `by-movement.md`, `_index.md` — генерируются скриптом `tools/build_indexes.py` из фронтматтера карточек (ADR-003). Ручное редактирование запрещено.
- **MCP-сервер:** `tools/mcp_server.py` — поиск по карточкам через эмбеддинги (`intfloat/multilingual-e5-large`). Запуск: `py tools/mcp_server.py --no-dns-protection` в активированном `.venv`. Порт `http://127.0.0.1:8000/mcp`.
- **Валидатор:** `tools/validate_cards.py` — сверяет имена регистров в карточках с реальной конфигурацией.

## 3. ⚠️ ПРАВИЛО ДЛЯ НОВОГО ЧАТА: НЕ ДЕЛАТЬ FETCH ВСЕГО РЕПОЗИТОРИЯ

## 5. Инструменты (tools/)

### 5.1. Пайплайн разбора PDF

```

PDF → tools/pdf_extract.py → .md с постраничной разметкой
→ tools/chunker.py → .chunks.json + .chunks.md
→ вручную через BDS → карточка в kb/unf30/

```

- **`pdf_extract.py`** — извлекает текст постранично, отсеивает виджеты (чат «Роман Месяткин»), пустые страницы, навигацию.
- **`chunker.py`** — разбивает на смысловые чанки 300–800 слов, склеивает мелкие, чистит мусор (`! ! !`, обрывки).
- Оба инструмента протестированы на двух PDF. Сырьё и чанки лежат в `_source/01_unf/03_external/`.

### 5.2. Валидация карточек по конфигурации

```

py tools\parse_config_xml.py   # XML → _meta/config_metadata.json (компактный индекс)
py tools\validate_cards.py     # сверка карточек с индексом

```

- **`parse_config_xml.py`** — читает XML-выгрузку из `_raw/unf30_xml/`, собирает `_meta/config_metadata.json`. Собирает документы, справочники, регистры, перечисления, реквизиты, ТЧ, движения.
- **`validate_cards.py`** — сверяет `## Движения` и `## Участие в регистрах` в карточках с реальной конфигурацией. **Работает: 0 ошибок.**

### 5.3. Индексы и ADR-003

- **`build_indexes.py`** — генерирует `by-synonym.md`, `by-movement.md`, `_index.md` из фронтматтера. Режимы: `--dry-run`, `--apply`, `--check`, `--inspect`. Валидирует против эталона `_meta/_expected/references.json`.
- **`migrate_synonyms.py`** — одноразовая миграция синонимов из индекса в карточки. Уже выполнена, все 34 старые карточки имеют поле `synonyms` во фронтматтере.

### 5.4. MCP-сервер

- **`mcp_server.py`** — MCP SDK v2 (`mcp>=2.0`). Транспорт streamable-http. Инструменты: `search_kb`, `get_card`, `kb_stats`. Эмбеддинги кэшируются в `.cache/`.
- **`check_mcp.py`** — проверка сервера без BDS (JSON-RPC на stdlib).
- **`requirements-mcp.txt`** — `mcp>=2.0`, `fastembed>=0.4`, `pyyaml>=6.0`, `numpy>=1.26`.
- **`requirements-pdf.txt`** — `pymupdf>=1.24`.

## 6. Кладовая УНФ (стратегический ресурс)

База статей по УНФ (пример: «Производство в мебельных компаниях» от «Идеи», `1c-idea.ru`).

**Как используем:** внешний источник. Скачиваем PDF/HTML в `_source/01_unf/03_external/` (агент не читает, ADR-002). Прогоняем через `pdf_extract.py` → `chunker.py`. Из чанков вручную (через BDS) формируем карточки. После — обновляем `synonyms` и `## Движения`.

**Что уже извлечено (всё `draft`):**
- Параметрические спецификации.
- Спецификации с полуфабрикатами.

**Что важно:** извлечённое из «Кладовой» попадает в базу сразу как `draft` — источник внешний, на практике в этой конфигурации не проверялся.

## 8. Правила имён и типов (из `conventions.md`)

- `id`: `unf30-<prefix>-<slug>`. `type` ≠ `prefix`.
- Имя файла: `<prefix>-<slug>.md`, без `unf30-`.
- Мета-файлы (`conventions.md`, `index.md`, `handover.md`, `checkpoints/*.md`, `decisions/*.md`) — без фронтматтера карточки (у ADR свой минимальный фронтматтер).
- Синоним вносится только если слово встречается в теле карточки (ADR-001, R1). «Синоним из головы» — запрещён.

## 9. Окружение и платформа

- **Windows**, работаем через `py` (python в PATH не прописан).
- **`.venv`** активируется через `.venv\Scripts\activate` в **cmd** (не PowerShell).
- **1С платформа 8.5** (не 8.3!). Это важно: API метаданных в 8.5 другой, обработка `.epf`, написанная под 8.3, не работает.
- **`.gitignore`** защищает от случайного попадания в Git: `_raw/`, `_meta/_drafts/`, `*.epf`, `*.cf`, `*.dt`, `*.zip`, `_source/01_unf/03_external/*.pdf`.
