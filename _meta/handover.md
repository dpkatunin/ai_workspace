# Паспорт проекта: База знаний 1С для RAG-агента

Этот файл — точка входа для нового чата или нового участника. Он описывает текущее состояние проекта, архитектуру и следующие шаги.

## 1. Что мы строим
Мы создаем базу знаний по 1С:УНФ 3.0 для RAG-агента (внедренца-аналитика). Репозиторий: `github.com/dpkatunin/ai_workspace`.
Главная цель: агент должен отвечать на вопросы по внедрению, опираясь на проверенные карточки, с обязательной цитатой (`id`) и статусом достоверности (`verified` / `draft`).

## 2. Архитектура (зафиксирована в ADR-001 и ADR-002)
- **Двухуровневый RAG:** `kb/` (общие знания) + `projects/` (память проектов).
- **Изоляция источника:** старые исходники лежат в `_source/` и **не читаются** агентом.
- **Типы карточек:** `object` (документы, справочники), `mechanism` (сквозные механизмы), `playbook` (процедуры), `pitfall` (грабли), `case` (паттерны).
- **Навигация:** иерархическая (карта `_meta/index.md` -> индекс раздела `_index.md` -> 1-3 карточки). Векторный поиск пока не используем (триггеры перехода — в ADR-001).

## 4. Следующие шаги (Фаза 2)
Приоритетные направления для дальнейшего наполнения:
1. **Углубление торгового контура:** Склад (ордерная схема, ячейки), Закупки (доп. расходы, корректировки), Ценообразование (виды цен, скидки).
2. **Углубление работ:** Акт выполненных работ, Сдельный наряд (зарплата).
3. **Переработка кейсов:** Перенос 15 кейсов из `_source/` в `kb/unf30/cases/` (по одному).

## 5. Как мы работаем (Workflow)
1. Я (Архитектор) генерирую ZIP-архив с новыми/измененными файлами.
2. Пользователь скачивает ZIP, распаковывает в локальный клон `C:\ai_workSpaceGitHub\ai_workspace` (с заменой).
3. Пользователь делает Commit и Push через GitHub Desktop.
4. Мы проверяем результат через fetch репозитория.
5. **Важно:** мы пишем карточки спринтами (по 3 штуки), чтобы не плодить ошибки и держать качество.
