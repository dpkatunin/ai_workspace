# Паспорт проекта: База знаний 1С для RAG-агента

Этот файл — точка входа для нового чата или нового участника.

## 1. Что мы строим
Мы создаем базу знаний по 1С:УНФ 3.0 для RAG-агента (внедренца-аналитика). Репозиторий: `github.com/dpkatunin/ai_workspace`.
Главная цель: агент должен отвечать на вопросы по внедрению, опираясь на проверенные карточки, с обязательной цитатой (`id`) и статусом (`verified` / `draft`).

## 2. Архитектура (ADR-001 и ADR-002)
- **Двухуровневый RAG:** `kb/` + `projects/`.
- **Изоляция источника:** `_source/` не читается агентом (только для ручного извлечения знаний).
- **Типы карточек:** `object`, `mechanism`, `playbook`, `pitfall`, `case`.
- **Навигация:** `_meta/index.md` → `kb/unf30/_index.md` → 1–3 карточки.
- **Промпт агента:** `_meta/navigator-prompt.md` — правила: открывать карточки, не использовать общие знания, статус из фронтматтера.

## 3. ⚠️ ПРАВИЛО ДЛЯ НОВОГО ЧАТА: НЕ ДЕЛАТЬ FETCH ВСЕГО РЕПОЗИТОРИЯ
`_source/` содержит ~60 файлов, которые НЕ участвуют в RAG. Fetch только `_meta/` и `kb/unf30/`. `_source/` не открывать **никогда** (ADR-002).

## 5. Кладовая УНФ (Стратегический ресурс)
Найдена база статей по УНФ (пример: «Производство в мебельных компаниях» от компании «Идея», `1c-idea.ru`).
**Значение:** Это огромный источник первичных данных для наполнения `_source/` и извлечения новых карточек.
**Что уже извлечено:** Механизм параметрических спецификаций и полуфабрикатов. Механизм назначения операций на исполнителей (Сдельный наряд).
**Что делать:**
1. Скачивать релевантные статьи в `_source/`.
2. Извлекать из них структурированные карточки (1 статья = 1-3 карточки).
3. Обновлять `by-synonym` и `by-movement`.
