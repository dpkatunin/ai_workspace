# Схема карточек

Все карточки — Markdown с YAML front matter. Фронтматтер — это «реквизиты элемента справочника»: по ним агент фильтрует и связывает, не читая тело.

Схема одна для обоих уровней (`level: kb` и `level: projects`). Различия — в правилах ID и индексации, см. ADR-004.

## Обязательные поля

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | Уникальный ID. Для `level: kb` — `<config>-<prefix>-<slug>` (`unf30-doc-realizaciya`). Для `level: projects` — `<project>-<prefix>-<slug>` (`alfa-pit-rezervirovanie`). См. `conventions.md` §1 и ADR-004 §5. |
| `config` | string | Конфигурация: `unf30`, `erp`, `zup`, ... |
| `type` | enum | `object`, `mechanism`, `playbook`, `pitfall`, `case`, `decision`, `project`. |
| `level` | enum | `kb` — общие знания, `projects` — конкретный проект. |
| `tags` | list | Свободные теги для отбора. |
| `status` | enum | `verified`, `draft`, `outdated`. Значения `raw` в схеме нет — сырьё живёт в `inbox/` (ADR-004 §2). |
| `updated` | date | Дата последнего изменения, `YYYY-MM-DD`. |

## Опциональные поля

| Поле | Тип | Описание |
|---|---|---|
| `config_version` | string | Минимальная версия конфигурации, например `">=3.0.12"`. |
| `synonyms` | list | Разговорные синонимы для поиска. |
| `related` | list | ID связанных карточек (граф). |
| `source` | string | Источник знания: ИТС, статья, проект. |
| `project` | string | ID проекта (только для `level: projects`). |

## Типы карточек

### `object` — объект метаданных или справочник
Документ, справочник, регистр. Отвечает на вопрос «что это и из чего состоит».
Секции: назначение, реквизиты, движения, связи, типовые ошибки (ссылки), источники.

### `mechanism` — механизм
Сквозная логика, которая не привязана к одному объекту: резервирование, скидки, ордерная схема, партионный учёт.
Секции: суть, где включается, как работает, подводные камни, связи.

### `playbook` — процедура
Пошаговое «как сделать». Отвечает на вопрос «как выполнить задачу».
Секции: когда применять, шаги, проверка результата, связанные грабли.

### `pitfall` — кластер грабель
Отображение «симптом → причина → решение». Кластер по теме, а не по разделу.
Каждая ошибка — отдельная секция с якорем `{#pit-xxx}`.
Секции: симптом, причина, решение, связанные карточки.

### `case` — паттерн из внедрения
Обезличенный опыт: контекст, решение, цифры, применимость.
Без маркетинга. Секции: контекст, решение, нестандартные приёмы, результаты, когда применять.

### `project` — паспорт проекта
Только для `level: projects`. Файл `projects/<slug>/_project.md`, `id` = `<project-slug>`.
Минимум полей, ссылки на ADR. **Паспорт не индексируется** — ни векторным поиском, ни `by-synonym` (ADR-004 §6).

### `decision` — ADR
Запись архитектурного решения проекта.
Секции: контекст, решение, альтернативы, последствия.

## Пример фронтматтера

```yaml
---
id: unf30-doc-realizaciya
config: unf30
config_version: ">=3.0.12"
type: object
level: kb
tags: [продажи, отгрузка, резерв, ндс]
synonyms: [реализация, расходная накладная, отгрузка]
status: verified
source: "ИТС, разд. Продажи"
updated: 2026-10-26
related: [unf30-pb-otgruzka-s-rezervom, unf30-pit-rezervirovanie]
---
```

# Карта базы знаний

Это первое, что читает агент. Здесь — что где лежит и куда идти.

## Уровни и каталоги

- **`kb/`** — общие знания по конфигурациям (рабочий, публичный).
- **`projects/`** — память конкретных проектов (рабочий, приватный).
- **`_meta/`** — правила, карта, навигатор, индексы, решения (служебный).

## Правила и архитектура

- **`_meta/schema.md`** — описание фронтматтера и типов карточек.

## Проекты

Структура `projects/` заложена ADR-004 и наполняется. Проекты живут в отдельном приватном репозитории `ai_workspace_projects`.

**MCP к `projects/` пока не подключён** (этап 0 по ADR-004): поиск идёт только по `kb/`. Подключение — после наполнения первого проекта.

Реестр проектов — `projects/_index.md` (создаётся по мере появления проектов). Личные методики — `projects/_personal/`.

## Как агент ходит по базе

0. **Новый чат без контекста?** Сначала прочитай `_meta/design/00-START-HERE.md` — это даст контекст за две минуты.
1. Читает этот файл.
2. Определяет тип вопроса: что / как / почему / пример.
3. Если вопрос вида «какие документы пишут в регистр X» — сразу `_meta/by-movement.md`, минуя `_index.md` раздела.
4. Иначе — открывает `_index.md` нужного раздела.
5. Подтягивает 1–3 карточки. **Открывает их, а не отвечает по индексу.**
6. Отвечает с цитатой (`id`) и статусом (`verified` / `draft`).

## Индексы

- `_meta/by-synonym.md` — синонимы → ID.
- `_meta/by-movement.md` — регистр → документы, которые в него пишут; плюс справочники как измерения.

> Оба индекса **генерируются** скриптом `tools/build_indexes.py` из фронтматтера и секции `## Движения` (ADR-003). Ручное редактирование запрещено. При изменении карточек — пересборка в том же коммите.

> Индексы покрывают **только `kb/`**. Синонимы проектов собираются в `projects/<slug>/_index.md` (ADR-004 §6) — клиентские строки не должны попадать в публичный репозиторий.
