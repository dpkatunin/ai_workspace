# Журнал решений (ADR)

> **ADR** (Architecture Decision Record) — это как **история изменений
> конфигурации**, но для архитектурных решений. Каждое важное решение
> записывается: что решили, почему, какие альтернативы отвергли.

## Формат записи

```markdown
## ADR-XXX. {Название решения}

**Дата:** YYYY-MM-DD
**Статус:** accepted | rejected | superseded | deferred

**Контекст:** что решали.

**Решение:** что выбрали.

**Альтернативы:** что отвергли и почему.

**Следствия:** что это меняет.
```

## ADR-001. Разделение Knowledge Base и Projects

**Дата:** 2026-10-22
**Статус:** accepted

**Решение:** отдельный уровень `01_projects/`. KB — переиспользуемые
знания. Projects — артефакты конкретных внедрений.

**Следствия:** два RAG-индекса (KB и Projects), правила маршрутизации.

## ADR-002. Три оси архитектуры (config / type / concept)

**Дата:** 2026-10-22
**Статус:** accepted

**Решение:** три ортогональные оси. `config` — какая конфигурация.
`type` — какой тип знания. `concept` — семантический тег.

**Следствия:** taxonomy.yaml с тремя осями, config_registry.yaml.

## ADR-008. Противоречия между KB и кейсом (M7-partial)

**Дата:** 2026-10-24
**Статус:** accepted (частично)

**Следствия:** новый тип связи `contradicts`. `_conflicts/`.

## ADR-011. Semantic Quality Assurance (M14)

**Дата:** 2026-10-25
**Статус:** accepted

**Решение:** три уровня строгости (Feedback Loop / KB Testing /
Golden Set). Типы ошибок: `hallucination_link` ≠ `hallucination_fact`.
UX: ручной запуск + напоминание. CI/CD не требуется.

**Следствия:** `_meta/feedback/`, `_meta/tests/`, `_meta/test_reports/`.

---

## ADR-012. Маршрутизация запросов (M7-full)

**Дата:** 2026-10-25
**Статус:** accepted

**Решение:**

1. Семь типов запросов (+ `history`).
2. Гибридная классификация (эвристика → LLM).
3. При 0 результатов — «честно + близкое + шире».
4. Связи: глубина 1 в контекст, глубина 2 в «кстати».

**Следствия:** пост-проверка slug (M14), предупреждения, feedback-записи.

## ADR-014. Генерация артефактов для 4 ролей (M13, расширение)

**Дата:** 2026-10-25
**Статус:** accepted (концепция зафиксирована)

**Решение:** M13 расширена на 4 роли.

| Роль ↕▾ | Что генерирует M13 ↕▾ |
|---|---|
| −Аналитик | Карта, gap, чек-лист, риски, резюме, карта стейкхолдеров, боли, сценарии, допущения, глоссарий (опционально) |
| Внедренец | Инструкции, чек-лист настройки, шпаргалка, протокол миграции, паспорт системы (черновик), реестр пользователей (черновик), сценарии UAT (черновик), протокол тестирования (черновик) |
| РП | Реестр рисков, статус, отчёт клиенту, план-график, change log (черновик), протокол сдачи, дашборд, реестр проблем (черновик), протокол эскалации |
| Директор | Сводка по портфелю, анализ компетенций, оценка эффективности, реестр лучших практик (черновик), реестр организационных ошибок (черновик) |
⚙

**Следствия:** M13 зависит от M9–M10 и universal-слоя. Приоритет — высокий.
