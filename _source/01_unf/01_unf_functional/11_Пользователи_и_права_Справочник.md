# 11. Пользователи и права. Справочник (Теория и логика работы)

## 1. Архитектура прав доступа
В 1С:УНФ 3.0 права доступа настраиваются через связку из трех звеньев:
1. **Профиль групп доступа:** Набор ролей (что можно делать: читать, создавать, проводить). Профили заданы в конфигурации и обновляются вместе с ней.
2. **Группа доступа:** Ссылается на профиль и содержит список сотрудников (участников). 
3. **Пользователь:** Включается в одну или несколько групп. Права складываются (объединение ролей).

*Важно:* Роли вручную не назначаются. Отдельной страницы «Роли» в карточке пользователя нет — набор ролей пересчитывается автоматически по группам доступа.

## 2. Первый пользователь и режимы входа
*   **Пустая база:** Пока в базе нет ни одного пользователя, вход в программу не требует ни имени, ни пароля, а сеанс открывается с полными правами. 
*   **Первый администратор:** При сохранении первого пользователя программа принудительно назначает ему роли «Администратор системы» и «Полные права». Без этого запись других пользователей блокируется.
*   **Аутентификация:** 
    *   *1С:Предприятие* (вход по логину и паролю).
    *   *Операционная система* (вход без пароля по учетной записи Windows).
    *   *OpenID / Токен* (для интеграций и сервисов).

## 3. Виды профилей
*   **Основные (11 шт.):** «Администратор», «Продажи», «Закупки», «Склад», «Производство», «Деньги», «Персонал», «Налоги», «Только просмотр», «Рабочее место старшего кассира», «Рабочее место операционного кассира».
*   **Дополнительные (18 шт.):** Не дают прав сами по себе, а *расширяют* основной профиль (назначаются в дополнение к нему). Например, «Редактирование цен документов (дополнительно)», «Возвраты от покупателей (дополнительно)». 
*   *Нюанс:* Профиль «Администратор» не дает права открывать внешние отчеты и обработки. Для этого нужно включить пользователя в дополнительный профиль «Открытие внешних отчетов и обработок».

## 4. Ограничение доступа на уровне записей (RLS)
Профили отвечают на вопрос «какие объекты сотрудник может открывать». RLS отвечает на вопрос «какие именно записи он увидит».
*   Включается флажком «Ограничивать доступ на уровне записей».
*   В УНФ 3.0 существует 11 видов доступа, по которым можно ограничивать (Организации, Склады, Кассы, Банковские счета, Виды цен и др.).
*   **Контрагенты и лиды ограничиваются не поштучно, а группами.** Для этого в окне настроек включаются флажки «Группы доступа контрагентов» и «Группы доступа лидов». После этого у контрагента появляется реквизит с группой доступа, и менеджер видит только свою часть клиентской базы.
*   *Внимание:* При включении RLS запускается фоновый пересчет ключей доступа по всей базе, что может временно замедлить работу.

## 5. Даты запрета изменений (Закрытие периодов)
Запрет правки документов прошлых периодов. Настраивается в «Настройках пользователей и прав»:
*   **Для всех пользователей** (включая администраторов).
*   **По пользователям** (точечно).
*   **По разделам** (например, только для продаж).
Дата может быть фиксированной («Произвольная дата») или «плавающей» (Конец прошлого месяца, Конец прошлой недели, Предыдущий день).

## 6. Интерфейс и поиск
Интерфейс настраивается **персонально** для каждого пользователя:
*   **Начальная страница:** Состав («Пульс бизнеса», «Текущие дела», «Новости») вычисляется при первом входе по правам и включенным возможностям.
*   **Поиск:** Работает через полнотекстовый индекс (включается в «Общих настройках»). Если свежие документы не находятся, нужно обновить индекс.
*   **Варианты интерфейса:** «Такси» (классический) и «Версия 8.5» (с открытием данных во вкладках). Смена варианта применяется после перезапуска программы.
*   **Заголовок приложения:** Поле в «Общих настройках», текст из которого выводится в заголовке окна (удобно для отличия рабочей базы от копии).
