# _source/01_unf/03_external — внешние материалы

## Что это

Сюда складываются внешние материалы по УНФ 3.0: PDF-статьи, скриншоты,
выгрузки с сайтов. Это **не** оригинальные файлы 1С и **не** дайджесты
из `01_unf_functional`.

## Чем отличается от `01_unf_functional`

- `01_unf_functional/` — структурированные дайджесты по разделам УНФ
  (введение, номенклатура, склад, производство и т.д.). Уже разобраны
  по темам, используются как источник для карточек.
- `03_external/` — «сырые» внешние материалы, ещё не разобранные.
  Сюда попадает PDF, из которого только предстоит сделать карточки.

## Как сюда попадают файлы

1. Находим статью/PDF по УНФ.
2. Сохраняем в `03_external/` с осмысленным именем.
3. Извлекаем текст скриптом `tools/pdf_extract.py` (см. ниже).
4. Разбираем на карточки (вручную через BDS или скриптом).
5. После разбора — материал остаётся здесь как история.

## Извлечение текста из PDF

Скрипт `tools/pdf_extract.py` извлекает текст постранично и отсеивает
пустые страницы (скриншоты, на которых текста нет). Без этого отсева
LLM получает пустоту и начинает галлюцинировать.

Установка зависимости (один раз, в активированном `.venv`):

```bat
py -m pip install -r tools\\requirements-pdf.txt
```

Запуск:

```
py tools\\pdf_extract.py "_source/01_unf/03_external/Производство в 1С_УНФ для мебельной компании.pdf"
```

Результат — `.md` рядом с PDF, с разделителями `<!-- page N -->`
и списком отсеянных страниц в шапке. Дальше этот `.md` разбирается
на карточки (вручную через BDS или скриптом `tools/chunker.py`).

## Почему не в RAG

По ADR-002 `_source/` не читается агентом. Карточки в `kb/` — единственный
источник знаний для RAG. `03_external/` — это «склад сырья», а не «полка
с готовыми ответами».
