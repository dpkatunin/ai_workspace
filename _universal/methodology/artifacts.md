## Итого: что генерирует M13

| Роль | Артефакты |
|---|---|
| **Аналитик** | checklist, stakeholders, pains, scenarios, assumptions, glossary (опц.), mapping, gap, roadmap |
| **Внедренец** | setup-checklist, module-cheatsheet, user-guides, migration-protocol (усл.), system-passport (черновик), users-rights (черновик), uat-scenarios (черновик), test-protocol (черновик) |
| **РП** | schedule, registry-risks, issues-log (черновик), escalation (шаблон, усл.), handover, dashboard, status, client-report |
| **Директор** | portfolio, competencies, effectiveness, best-practices (черновик), org-mistakes (черновик), practice-report |
| **Сквозные** | system-passport (черновик), issues-log (черновик), registry-risks, registry-decisions (не M13 — вручную) |

**Что M13 НЕ генерирует:** сырьё (`notes`, `as-is`), факты (`meetings`),
решения (`registry-decisions`, `to-be`, `requirements`, `tz-modifications`).
Это создаёт человек.

## Связь с universal-слоем

Для каждого артефакта из списка M13 — есть шаблон в `_universal/templates/`.
Шаблон задаёт структуру, M13 заполняет данными проекта и KB.

**Аналогия из 1С:** шаблон — это **макет печатной формы**, M13 — это
**заполнение макета данными**. Без макета — нечего заполнять. Без данных —
пустой макет.
