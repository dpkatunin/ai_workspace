# Роли в проекте внедрения

> **Что это:** четыре роли, которые участвуют в проекте. У каждой —
> свои задачи, свой горизонт планирования, свои требования к системе.
>
> **Зачем:** M13 генерирует артефакты для каждой роли. M17 агрегирует
> данные по ролям. Без понимания ролей — непонятно, «для кого» генерировать.
>
> **Аналогия из 1С:** это как **профили групп доступа** — разные роли,
> разные права, разные рабочие места. Только для проекта, не для базы.
>
> **⚠️ Важно:** архитектурные детали (что критично, чего не хватает) —
> в `_meta/specs/ROLES.md`. Здесь — только «что делает роль».
>
> **Исправлено:** 2026-10-25 (указано, что артефакты директора — когда
> M17 будет реализован)

---

## Четыре роли

### 1. Аналитик

**Кто:** собирает требования, описывает процессы AS-IS/TO-BE, готовит
карту соответствия и gap-анализ.

**Горизонт:** один проект, этап обследования и моделирования (1–3 недели).

**Задачи:**
- Провести обследование клиента (вопросы, интервью, заметки).
- Описать текущие процессы (AS-IS).
- Сопоставить процессы с модулями 1С (карта соответствия).
- Найти разрывы (gap-анализ).
- Сформировать требования (ФТ, ТЗ на доработку).
- Предложить модель TO-BE.

**Какие артефакты создаёт:**
- `checklist.md`, `filled-checklist.md`, `notes.md` (этап 1).
- `stakeholders.md`, `pains.md`, `scenarios.md`, `assumptions.md`,
  `glossary.md` (этап 1, M13).
- `mapping.md`, `gap.md`, `roadmap.md` (этап 2, M13).
- `to-be.md`, `requirements.md`, `tz-modifications.md` (этап 2, вручную).

---

### 2. Внедренец

**Кто:** настраивает систему, тестирует, обучает пользователей, запускает.

**Горизонт:** один проект, этап настройки и запуска (2–6 недель).

**Задачи:**
- Настроить 1С под требования (справочники, документы, регистры, права).
- Провести миграцию данных (если нужно).
- Протестировать (UAT).
- Обучить пользователей, написать инструкции.
- Запустить (go-live).
- Поддержать первые дни после запуска.

**Какие артефакты создаёт:**
- `setup-checklist.md`, `module-cheatsheet.md`, `user-guides/*.md` (M13).
- `system-passport.md`, `users-rights.md` (черновики, M13).
- `migration-protocol.md` (условно, M13).
- `uat-scenarios.md`, `test-protocol.md` (черновики, M13).

---

### 3. Руководитель проекта (РП)

**Кто:** отвечает за сроки, бюджет, риски, коммуникацию с клиентом.

**Горизонт:** один проект, весь цикл (1–6 месяцев).

**Задачи:**
- Спланировать проект (этапы, ресурсы, зависимости).
- Контролировать прогресс (что сделано, что нет).
- Управлять рисками (выявить, оценить, митигировать).
- Управлять изменениями (клиент просит новое — оценить влияние).
- Отчитываться перед клиентом и руководством.
- Сдавать проект (акты, приёмка).

**Какие артефакты создаёт:**
- `schedule.md` (план-график, M13).
- `change-log.md` (совместно с внедренцем).
- `issues-log.md` (совместно с внедренцем).
- `registry-risks.md` (M13).
- `escalation.md` (шаблон, M13, условно).
- `handover.md` (M13).
- `dashboard.md` (генерируется, M9+M13).
- `status.md` (M13).
- `client-report.md` (M13).

---

### 4. Руководитель практики / Директор

**Кто:** отвечает за портфель проектов, качество, компетенции команды,
развитие практики.

**Горизонт:** все проекты, все клиенты, долгосрочное развитие (год и более).

**Задачи:**
- Управлять портфелем проектов (загрузка, приоритеты, маржинальность).
- Контролировать качество (стандарты, методология, повторяемость).
- Развивать компетенции команды (обучение, наставничество).
- Развивать базу знаний (накапливать опыт, тиражировать лучшие практики).
- Принимать решения о ресурсах (кого на какой проект).
- Оценивать эффективность практики (выручка, маржа, удовлетворённость).

**Какие артефакты создаёт:**
- `portfolio.md` (сводка по портфелю, M17+M13) — **когда M17 будет
  реализован** (сейчас M17 отложен, ADR-016).
- `competencies.md` (анализ компетенций, M17+M13) — **когда M17 будет
  реализован**.
- `effectiveness.md` (оценка эффективности, M17+M13) — **когда M17 будет
  реализован**.
- `best-practices.md` (реестр лучших практик, M16+M13+вручную) — **когда
  M16 будет реализован** (сейчас M16 отложен, ADR-015).
- `org-mistakes.md` (реестр организационных ошибок, M16+M13+вручную) —
  **когда M16 будет реализован**.
- `practice-report.md` (отчёт по практике, M17+M13) — **когда M17 будет
  реализован**.

**⚠️ Важно:** артефакты директора сейчас **не генерируются**, потому что
M16 и M17 отложены. Они появятся, когда механизмы будут реализованы.
