# Механизм: Спецификации с полуфабрикатами

## Суть

Спецификация с полуфабрикатами — это многоуровневая спецификация. Готовая продукция (например, шкаф) состоит не только из материалов, но и из **полуфабрикатов** — изделий, которые сами производятся по собственной спецификации.

Пример из источника (мебель):

- **Шкаф** = фасад + корпус + фурнитура Blum. Операции: сборка, установка.
- **Фасад** — полуфабрикат: МДФ + эмаль. Операции: распил, нанесение эмали.
- **Корпус** — полуфабрикат: кромка + ЛДСП. Операции: распил ЛДСП, оклейка кромки.

## Где включается

- Справочник **«Спецификации»** (`unf30-cat-specifikaciya`) — подчинён справочнику «Номенклатура».
- Владелец спецификации — номенклатура с типом **«Запас»** или **«Работа»** (не «Услуга», не «Набор»).

## Четыре вида строк состава

Подтверждено перечислением `ТипыСтрокСоставаСпецификации` — ровно четыре значения:

| Тип строки | Что означает |
|---|---|
| **Материал** | Закупаемый запас, списывается напрямую |
| **Сборка** | Полуфабрикат, производится по собственной спецификации |
| **Узел** | Виртуальный набор материалов (не хранится на складе отдельно) |
| **Расход** | Внешние работы и услуги (комментарий в конфигурации: «Внешние работы и услуги») |

Для полуфабрикатов используется строка **«Сборка»** — она и делает спецификацию многоуровневой.

## Как задаётся вложенность

В табличной части `Состав` справочника «Спецификации» есть реквизит **`Спецификация`** (ссылка на тот же справочник). Для строки типа «Сборка» указывается спецификация, по которой производится этот полуфабрикат. Так и получается многоуровневость.

## Ключевые реквизиты справочника «Спецификации»

| Реквизит | Назначение |
|---|---|
| `Владелец` (Owner) | Номенклатура — продукция или работа |
| `ХарактеристикаПродукции` | Характеристика изделия |
| `ВидПроизводства` | Ссылка на `Справочник.ВидыПроизводства` |
| `БазоваяСпецификация` | Ссылка на другую спецификацию. **В конфигурации называется «Базовая», не «Основная»** |
| `ЭтоШаблон` | Признак шаблона |
| `Недействителен` | Спецификация выведена из работы |
| `Заказ` | Привязка к `ЗаказПокупателя` или `ЗаказНаПроизводство` |
| `ИспользуетсяРасширение` | Признак использования формул/расширения (см. `unf30-mech-parametricheskie-specifikacii`) |

Табличная часть `Состав`: `ТипСтрокиСостава`, `Номенклатура`, `Характеристика`, `ЕдиницаИзмерения`, `Спецификация`, `Количество`, `КоличествоПродукции`.

## Резервирование материалов

Из источника (стр. 5–6): «Смысл Заказа на производство состоит в том, что он, во-первых, планирует операции, которые необходимо выполнить. Во-вторых, он резервирует и создает потребность в материалах».

То есть при создании заказа на производство по многоуровневой спецификации система видит потребность не только в верхнеуровневых материалах, но и в материалах для полуфабрикатов.

## Требует проверки на практике (L3)

> Структура подтверждена XML. Поведение — нет.

- Глубина вложенности полуфабрикатов: 2 уровня — предел или больше? (В источнике — два.)
- Видит ли заказ на производство потребность в материалах **полуфабрикатов** — на практике.
- Резервируются ли материалы полуфабрикатов при создании заказа.
- Как выглядит документ «Производство» для многоуровневой спецификации: одно производство на всё или отдельное на каждый полуфабрикат.

## Связи

- `unf30-cat-specifikaciya` — справочник спецификаций, виды строк.
- `unf30-mech-parametricheskie-specifikacii` — параметрические спецификации (соседний механизм).
- `unf30-doc-zakaz-na-proizvodstvo` — планирование и резервирование материалов.
- `unf30-doc-proizvodstvo` — факт выпуска.
- `unf30-pit-specifikacii` — грабли спецификаций.
