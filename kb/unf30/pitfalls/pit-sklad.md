# Грабли: склад

Кластер ошибок складского контура: инвентаризация, пересортица, ячейки, ордера, перемещения.

## {#pit-inventarizaciya} Инвентаризация не меняет остатки

**Симптом:** Провели «Инвентаризацию запасов», а товар на складе в учёте не изменился.

**Причина:** У документа нет проведения. Он только фиксирует разницу между учётным и фактическим количеством.

**Решение:** На основании инвентаризации создать «Оприходование» (на излишки), «Списание» (на недостачи) или «Пересортицу».

## {#pit-peresortica} Пересортица «на основании» не проводится

**Симптом:** Создали «Пересортицу» из инвентаризации, а документ не проводится (ошибка по пустому счёту).

**Причина:** Автозаполнение разбивает пару на две односторонние строки: в одной пусто поле приходуемой номенклатуры, в другой — списываемой.

**Решение:** Удалить автозаполнение и вручную свести обе номенклатуры в одну строку кнопкой «Сопоставить 2 строки».

## {#pit-komplektaciya-vs-sborka} Путаница между «Комплектацией» и «Сборкой»

**Симптом:** Пытаются собрать мебель по спецификации, используя «Комплектацию запасов».

**Причина:** Это два разных документа. «Комплектация» — простая пересборка (доступна всегда). «Сборка» — производственный документ (требует включения подсистемы «Производство»).

**Решение:** Для физической сборки по рецептам — «Сборка» (со спецификациями). Для комплектации подарочных наборов — «Комплектация».

## {#pit-yacheyki} Не включается флажок «Учёт по ячейкам»

**Симптом:** Пытаются включить ячейки на обычном складе, программа не даёт.

**Причина:** Ячейки работают **только** на ордерных складах.

**Решение:** Включить ордерную схему на складе, затем — учёт по ячейкам. Если по складу уже есть движения — создать новый склад.

## {#pit-peremeshenie-order} Перемещение не проводится из-за ордера

**Симптом:** Создали «Перемещение запасов», а программа требует ордер.

**Причина:** В карточке склада-отправителя или получателя включена ордерная схема при перемещении.

**Решение:** Сначала оформить складской ордер (приходный или расходный), затем перемещение. Либо создавать перемещение на основании ордера.

## {#pit-ostтки-po-yacheykam} Остаток по ячейкам не сходится с общим остатком

**Симптом:** В отчёте «Склад» общий остаток один, а в «Остатках по ячейкам» — другой.

**Причина:** Расхождение между регистром «Запасы» (количество + сумма) и регистром «Запасы на складах» (адресный, только количество). Возможно, движение прошло без указания ячейки.

**Решение:** Проверить движения по документам. Найти документы, где ячейка не указана (например, при списании), и перепровести.

## {#pit-hozyaystvennaya-operaciya} Хозяйственная операция не проверяется на смысл

**Симптом:** Списание порчи провели через операцию «Списание имущества», суммы ушли не туда.

**Причина:** Справочник «Хозяйственные операции» не проверяет логику при проведении — он просто задаёт корреспонденцию счетов.

**Решение:** Внимательно выбирать нужную операцию в шапке: «Списание запасов» для порчи, «Списание на расходы» для материалов.

## {#pit-nakladnaya-bez-ordera} Накладная без ордера на ордерном складе

**Симптом:** Накладная проведена, но кладовщик не видит движения по ордеру, а в отчётах расхождение.

**Причина:** Накладная на ордерном складе всё равно проводится (с предупреждением). Разрывается цепочка «ордер → накладная».

**Решение:** Соблюдать порядок: сначала ордер (физическое движение), затем накладная на основании ордера (финансовое движение). Не игнорировать предупреждение.

## {#pit-yacheyki-bez-summy} «Запасы» и «Запасы на складах» расходятся

**Симптом:** В «Запасах» сумма есть, а в «Запасах на складах» — нет (или наоборот).

**Причина:** Разные регистры пишутся разными документами. «Запасы» — накладными, «Запасы на складах» — ордерами. Если провести только один документ из пары, регистры разойдутся.

**Решение:** Проверять движения по обоим регистрам. На ордерном складе должны быть проведены и ордер, и накладная.
