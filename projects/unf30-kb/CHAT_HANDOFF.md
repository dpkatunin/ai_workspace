## Что за проект

ИИ-база знаний (RAG) по конфигурации 1С **УНФ 3.0**. Пользователь —
внедренец с 25-летним опытом. Цель: давать проверяемые ответы, не галлюцинировать.

**Главный вывод:** поведение нельзя гарантировать промптом. Правильность
обеспечивается **кодом и структурой данных**.

## Ключевые решения (не пересматривать без причины)

1. **STRUCT → SQLite**, не в векторную БД. Точный поиск по именам надёжнее семантики.
2. **`Раскрытие` из выгрузки не храним** — граф из `Типы` + `СвойстваОбъекта`.
3. **`СвойстваОбъекта` — в колонки + JSON.** Без `register_kind` модель галлюцинирует.
4. **ID фактов стабильные:** `obj:Документ.ЗаказКлиента`, `attr:…`, `move:…`, `link:…`.
5. **Лимит 10–15 КБ на ответ MCP-инструмента.** Большие массивы обрезаются с `truncated`.
6. **Валидатор имён — код.** Все `ПолноеИмя` в ответе проверяются по `objects.full_name`.
7. **`ijson`, не `json.load`.** Файлы полной выгрузки 10–50 МБ.

## Что делать (следующий шаг)

Пользователь не может передать в чат файлы выгрузки (2.91 МБ и 13 МБ — лимит
сообщения). Поэтому:

1. **Пользователь локально запускает `survey.py`** на папке с выгрузкой:
```

py survey.py --input C:\путь\к\экспорту\ --output survey.json

```
Присылает `survey.json` (5–15 КБ) в чат.

2. По отчёту **уточняем ingest** (края, редкие поля, аномалии).

3. **Пользователь запускает `slice.py`** на одном проблемном объекте:
```

py slice.py --input C:\путь\к\экспорту\Документ.ЗаказКлиента.json ^
--full-name Документ.ЗаказКлиента ^
--output sample.json --compact

```
Присылает `sample.json` (20–40 КБ).

4. **Собираем MCP-сервер** (`tools/struct_mcp.py`) — 8 инструментов из `tools.md`.

5. **Собираем валидатор имён** — пост-процессор ответа.

## Правила общения

- Не использовать старые BDS-инструменты для записи файлов без просьбы.
- Не выдумывать имена объектов 1С. Если чего-то нет в фактах — писать «нет данных».
- Объяснять сложные ИИ-термины через аналогии из 1С, базовые понятия 1С — не объяснять.
- Отвечать по-русски.
