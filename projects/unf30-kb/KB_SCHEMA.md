# KB_SCHEMA — соглашение о скелете карточек KB (v2, 2026-11-08)

KB остаётся эссе по сути, но каждая карточка получает проверяемый скелет во
фронтматтере. Программная проверка (verify_kb.py) закрывает ЯКОРЯ — имена и
ссылки. Рассуждение в прозе кодом не проверяется и не проверяется никогда:
это осознанная граница системы.

## Формат карточки

```markdown
---
id: doc-realizaciya
type: doc                # doc | cat | mech | pb | pit | case
config: unf30
objects:                 # ПолныеИмена объектов УНФ — якоря в STRUCT
  - Документ.РеализацияТоваровУслуг
  - Справочник.Номенклатура
links:                   # id других карточек (по имени файла без .md)
  - pit-ceny
verified_against: "3.0, выгрузка 2026-11-08"
---
# Реализация (товаров, услуг, комиссия)
...эссе как раньше...
```

Фронтматтер — подмножество YAML: только `ключ: значение` и плоские списки
`- элемент`. Многострочные значения не поддерживаются — их в тело карточки.

## Правила

1. `id` = имя файла без `.md`. Допустим префикс `unf30-` (исторический): `unf30-mech-ordernaya-shema` для `mech-ordernaya-shema.md` — verify_kb принимает обе формы. Новые карточки делайте без префикса.
2. `type` — префикс оси type: doc-, cat-, mech-, pb-, pit-, case-.
3. `objects` — только объектные имена (Вид.Имя, 2 сегмента). Глубокие пути
   (реквизиты, значения перечислений) намеренно НЕ якорятся на этом этапе —
   им место в claims (будущий этап), сейчас они валидируются линтом текста
   (kb_lint) как раньше.
4. `links` — стебель другой карточки; verify_kb проверяет существование файла.
5. `verified_against` — штамп последней сверки с конфигурацией. Не обязателен,
   но verify_kb предупреждает о его отсутствии (мягко, не ошибка).
6. Карточка БЕЗ фронтматтера — легаси. Не ошибка: verify_kb выводит её в
   список «нет скелета». Миграция оппортунистическая: карточка получает
   скелет, когда её следующий раз касаются работы (или по предложениям
   kb_anchors_propose.py).

## Что это даёт при смене релиза

verify_kb.py после пересборки struct.db показывает: какие ЯКОРЯ умерли, в
каких карточках, с подсказками похожих имён. Триаж — точечный (до якоря),
а не перечитывание корпуса. Дифф релиза (diff_struct.py) + мёртвые якоря
(verify_kb) = исчерпывающий триаж-отчёт.
