# Kimi Code: как задавать вопросы по УНФ 3.0 (памятка)

## Разовая настройка (5 минут, один раз)

1. Убедитесь, что из последнего ZIP распакованы:
   - `ai_workspace/.kimi-code/mcp.json`  (три сервера: struct-unf30, help-unf30, unf30-kb)
   - `ai_workspace/AGENTS.md`            (правила ответов для агента)
2. Откройте Kimi Code Desktop → **Choose folder** → `C:\ai_workSpaceGitHub\ai_workspace`.
3. При первом запуске Kimi Code покажет запрос доверия (workspace trust) — в нём
   перечислены наши MCP-серверы. Нажмите **Trust this folder**.
4. **Начните НОВУЮ сессию.** Серверы подхватываются только в новых сессиях.
5. Проверка: в CLI выполните `/mcp` (в Desktop — панель MCP). Должно быть:
   - `struct-unf30` — connected (запускается сам через stdio, окно PowerShell НЕ нужно)
   - `help-unf30` — connected (тоже сам)
   - `unf30-kb` — connected, только если запущено его окно:
     `.venv\Scripts\python.exe tools/mcp_server.py --no-dns-protection`
     (если не запущен — не страшно, слои STRUCT и HELP главные)

Если `struct-unf30`/`help-unf30` в статусе failed — смотрите раздел «Если не завелось».

## Как формулировать вопросы

Просто пишите по-русски, как коллеге-внедренцу. AGENTS.md уже говорит агенту,
куда ходить за фактами. Хорошие формулировки:

| Тип вопроса | Пример | Куда пойдёт агент |
|---|---|---|
| Структура объекта | «Какие реквизиты у Документ.ЗаказПокупателя?» | struct-unf30 → get_object |
| Движения | «Какие регистры двигает ЗаказПокупателя?» | struct-unf30 → get_document_movements |
| Кто пишет в регистр | «Какие документы пишут в РегистрНакопления.ЗапасыНаСкладах?» | struct-unf30 → get_register_writers |
| Как пользоваться | «Как в УНФ зарезервировать товар по заказу покупателя?» | help-unf30 → help_search → help_get_article |
| Проверка имени | «Есть ли Справочник.Товары в УНФ?» | struct-unf30 → validate_names (ответ: нет данных) |

## Контроль качества ответа (на что смотреть)

1. **fact_id.** В ответе должны быть ссылки вида `obj:Документ.ЗаказПокупателя`,
   `help:Documents/ЗаказПокупателя/Ext/Help/ru.html`. Нет ссылок — ответ не проверен.
2. **«Нет данных» вместо выдумки.** Если агент пишет про объект, которого нет
   в конфигурации (напр. `Документ.ЗаказКлиента` из УТ 11), — это сбой, сообщите мне.
3. **validate_names.** На финальном ответе агент обязан прогнать имена через
   валидатор; если пропустил — напомните: «прогони имена через validate_names».

## Пять тестовых задачек для приёмки (с эталоном)

1. «Какие регистры двигает Документ.ЗаказПокупателя?»
   Эталон: список регистров через get_document_movements (их ~51).
2. «Есть ли в УНФ Справочник.Товары?»
   Эталон: «нет данных», валидатор unknown; агент предложит `Справочник.Номенклатура`.
3. «Как оформить продажу через РМК?»
   Эталон: help_search находит статьи подсистемы РМК; ответ со ссылками help:...
4. «Какие реквизиты у Документ.РасходнаяНакладная и какие у них типы?»
   Эталон: get_object + types из attribute_types.
5. «Какие документы пишут в РегистрНакопления.ЗапасыНаСкладах?»
   Эталон: get_register_writers, список документов (РасходнаяНакладная и др.).

## Если не завелось

| Симптом | Причина | Лечение |
|---|---|---|
| Серверов нет в /mcp | Старая сессия | Начать новую сессию (серверы подхватываются только при старте) |
| failed у struct/help | Нет доверия папке | Переоткрыть папку и подтвердить Trust |
| failed у struct/help | Занят порт/битый путь | Проверить пути в .kimi-code/mcp.json (там абсолютные, C:\ai_workSpaceGitHub\...) |
| unf30-kb failed | Не запущено окно KB-сервера | Запустить tools/mcp_server.py (или игнорировать) |
