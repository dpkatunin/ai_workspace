# Регламент эксплуатации unf30-kb

Документ этапа эксплуатации. Строительство и приёмка закрыты (5 задачек + 3 стресс-теста,
27 имён провалидировано answer_guard, 0 подтверждённых галлюцинаций). Дальше система
работает на реальных внедренческих задачах. Обновлять при появлении новых практик —
только добавлять, историю не переписывать.

Все команды — из корня workspace `C:\ai_workSpaceGitHub\ai_workspace`, PowerShell,
`chcp 65001` + `python -X utf8` (UTF-8 дисциплина, см. PROJECT_STATE 2026-11-05).

## 1. Старт рабочей сессии (поднять контур)

Три окна PowerShell, три сервера:

```powershell
# KB (порт 8000) — 43 ручные карточки
.venv\Scripts\python.exe tools/mcp_server.py --no-dns-protection

# STRUCT (порт 8001) — 9 инструментов
.venv\Scripts\python.exe projects/unf30-kb/struct/struct_mcp.py --db projects/unf30-kb/struct/data/struct.db --port 8001

# HELP (порт 8002) — 5 инструментов
.venv\Scripts\python.exe projects/unf30-kb/help/help_mcp.py --db projects/unf30-kb/help/data/help.db --port 8002
```

Проверка: в клиенте (Kimi Code / BDS) видны инструменты struct-* (9 шт.) и help-* (5 шт.).
Рестарт MCP обязателен после каждой заливки/пересборки соответствующей БД.

## 2. Роутинг вопросов по слоям

| Тип вопроса | Слой | Инструменты |
|---|---|---|
| «Есть ли объект / какие реквизиты / кто пишет в регистр / какие движения» | STRUCT | search_objects, get_object, get_document_movements, validate_names |
| «Как настроить / как работает механизм (по справке)» | HELP | help_search → help_get_article, help_get_object_articles |
| «Методика, подводные камни, чужой опыт» | KB | поиск по kb/unf30/ |
| UI-инструкции (меню, кнопки) | слои НЕ покрывают | честное «нет данных», источник — ИТС/релиз-ноты |

**ИС МП — особая зона.** HELP по ИСМП в дампе пуст/кривой (вендорский copy-paste из
ВетИС/ЕГАИС, подтверждено SQL-контролем 2026-11-07). Единственная корректная статья —
«Панель администрирования ИС МП». Канал для ИС МП: KB-слой методик + ИТС/ЦРПТ,
STRUCT — для имён объектов и реквизитов.

## 3. Правило доверия к справке (AGENTS.md №5)

«Привязке статьи верь, содержимому — после сверки»: перед цитированием содержимого
help-статьи сверять её тему с синонимом объекта из get_object; при расхождении —
пометить «статья нерелевантна объекту» и не использовать. Частных костылей под
конкретные подсистемы не делаем — правило универсально.

## 4. Контроль ответа агента (answer_guard v1.1)

Перед принятием ответа, содержащего имена объектов 1С:

```powershell
# вариант 1: ответ в файле draft.md → аннотированный Markdown
.venv\Scripts\python.exe -X utf8 projects/unf30-kb/struct/answer_guard.py --annotate draft.md

# вариант 2: строгая проверка (exit 2 при unknown → ответ НЕ принимать, вернуть агенту)
.venv\Scripts\python.exe -X utf8 projects/unf30-kb/struct/answer_guard.py --strict draft.md
```

Ожидаемо: `unknown 0` → ответ можно принимать. `warn` (объект-префикс есть, хвост не
подтверждён: формы и т.п.) — не блокер, но точка внимания.

Известные границы v1.1 (не баги, патч отложен):
- имена без префикса вида («справочник СервисПровайдерыСУЗ») экстрактор не ловит;
- у deep-resolved записей дамп полный, у exact-match компактный (косметика).

## 5. Если агент сказал «нет данных» — работа с дырами

Не принимать на веру и не считать провалом — фиксировать в `projects/unf30-kb/gaps.md`
(дата, вопрос, слой, что искали, как закрыли). Типовые разрешения:

| Причина дыры | Действие |
|---|---|
| Объект есть в конфигурации, но не в STRUCT (напр. регистры) | довыгрузка через экспортёр → ingest (раздел 6) |
| Методика/кейс не покрыт | новая KB-карточка (раздел 7) |
| Справка кривая/пустая (ИСМП и подобное) | источник ИТС/ЦРПТ; не цитировать help; запись в gaps.md |
| Морфология FTS («резервировать» ≠ «зарезервировать») | перефразировать запрос; нормализация FTS — бэклог, низкий приоритет |

## 6. Довыгрузка данных (когда нужен полный граф)

Экспортёр Romandredan/1c-metadata-json-exporter → папка (напр. `C:\obmen\json_...`) →

```powershell
.venv\Scripts\python.exe projects/unf30-kb/struct/ingest.py --input <папка> --db projects/unf30-kb/struct/data/struct.db
```

- Это ДОЗАЛИВКА: пересборка НЕ нужна; unresolved object_links (890 шт., ссылки на
  незалитые регистры) закроются автоматически через resolve_links.
- Пересборка нужна ТОЛЬКО при изменении маппинга полей (ingest пропускает существующие
  full_name без обновления).
- После заливки: рестарт MCP 8001, контроль — verify.py из папки struct
  (`..\..\..\.venv\Scripts\python.exe verify.py`).

## 7. Пополнение KB из реальных кейсов

Кейс решён → карточка в `kb/unf30/` с префиксом типа (doc-, cat-, mech-, pb-, pit-,
case-). Минимум: симптом, причина, решение, ссылки на факты (obj:/attr:/link: ID).
Особый приоритет — ИС МП (HELP там не источник). Карточка без проверяемых ссылок —
дефект.
