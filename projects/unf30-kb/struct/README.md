# STRUCT — слой структуры конфигурации 1С в базе знаний

Этот модуль — **слой STRUCT** для RAG-системы по 1С. Он превращает JSON-выгрузку
метаданных (от `1c-metadata-json-exporter`) в типизированную базу фактов в SQLite,
по которой работает MCP-сервер и через который агент отвечает проверяемыми фактами.

## Что здесь лежит

| Файл | Назначение |
|---|---|
| `schema.sql` | DDL SQLite: config, objects, attributes, attribute_types, tabular_sections, movements, object_links, enum_values, predefined |
| `_common.py` | Общие утилиты (потоковый итератор объектов через ijson) |
| `survey.py` | **Диагностика**: даёт компактный отчёт 5–15 КБ по папке с JSON (для передачи в чат) |
| `slice.py` | Вырезает один объект по `ПолноеИмя` из большого файла |
| `ingest.py` | Потоковый импорт JSON → SQLite |
| `architecture.md` | Конвейер, слои, валидатор |
| `tools.md` | Спецификация MCP-инструментов + лимиты ответов |

## Быстрый старт

```powershell
# 1. Установить зависимости (один раз)
py -m pip install -r requirements.txt

# 2. Сделать структурный отчёт по папке с выгрузкой
py survey.py --input C:\путь\к\экспорту\ --output survey.json

# 3. (Опционально) посмотреть один объект
py slice.py --input C:\путь\к\экспорту\Документ.ЗаказКлиента.json ^
             --full-name Документ.ЗаказКлиента ^
             --output sample.json --compact

# 4. Импортировать всё в SQLite
py ingest.py --input C:\путь\к\экспорту\ --db data\struct.db
```

## Ключевые принципы

1. **Ответ = факт + ID + источник.** Каждая строка в БД — это факт с уникальным ID
(например, `obj:Документ.ЗаказКлиента`), на который модель ссылается.
2. **Инструменты возвращают факты, а не чанки.** Никаких «прочитай XML кусками».
3. **Лимит на ответ инструмента — 10–15 КБ.** Большие массивы обрезаются с флагом
`Обрезано: true`.
4. **Валидация кодом.** Все `ПолноеИмя` в ответе модели проверяются через словарь
`objects.full_name`. Неизвестное имя → ответ блокируется.
