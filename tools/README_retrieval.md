# Лексический baseline-ретривер (Спринт 8, шаг 2)

## Что это

Проверка «тянет ли база» **без эмбеддингов и LLM**. Вопрос → top-3 карточек по:

1. Точному вхождению синонима (подстрока для многословных)
2. Пересечению токенов title / synonyms / body
3. IDF-взвешиванию (редкие токены ценнее частых)

## Запуск

    py tools\\retrieval_baseline.py
    py tools\\retrieval_baseline.py --top-k 5
    py tools\\retrieval_baseline.py --show-all
    py tools\\retrieval_baseline.py --question "почему цена не подтянулась"

## Метрика

`hit@3` = доля вопросов, где ожидаемая карточка попала в top-3.

- **≥ 80%** — база готова, можно добавлять эмбеддинги и LLM-слой
- **60–80%** — есть точечные дыры, чинить синонимы/карточки
- **< 60%** — проблема в базе, не в ретривере

## Как читать провалы

- `MISS` с высоким score у «неправильной» карточки → пересекающиеся синонимы, разводить expected
- `MISS` с низким score у всех → в базе нет подходящей карточки (нужна новая)
- `MISS` у draft-карточки → проверить, не пора ли её верифицировать

## Что НЕ делает

- Не использует эмбеддинги (следующий шаг)
- Не использует LLM (следующий шаг)
- Не читает `_source/` (ADR-002)
- Не пишет индексы — только читает карточки

## Ограничения baseline

- Усечение токенов до 5 символов — грубое, но для 34 карточек работает
- Морфология не настоящая: «цены» и «цена» сольются, а «ценообразование» — нет
- Нет понимания отрицаний («цена НЕ подтянулась» = «цена подтянулась» — для лексики это одно и то же)

Эти ограничения — причина, зачем на следующем шаге эмбеддинги.
